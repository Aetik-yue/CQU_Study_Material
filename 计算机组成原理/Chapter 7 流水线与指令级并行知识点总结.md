## 1. 流水线基本概念

### 知识点讲解

**流水线（Pipeline）** 是将指令执行过程分解为多个阶段，不同指令的不同阶段重叠执行，从而提高指令吞吐量的技术。

> **通俗理解**：流水线就像工厂的装配线——不是等一辆车完全造好才开始造下一辆，而是每个工位同时处理不同的车。

### 经典五级流水线

| 阶段 | 英文 | 功能 |
|------|------|------|
| **IF** | Instruction Fetch | 取指令 |
| **ID** | Instruction Decode | 译码、读寄存器 |
| **EX** | Execute | 执行运算或计算地址 |
| **MEM** | Memory Access | 访存 |
| **WB** | Write Back | 写回寄存器 |

### 流水线性能

**理想加速比** = 流水线级数

**实际加速比** < 理想值，因为存在：
- 流水线寄存器延迟
- 冒险（Hazards）导致的停顿

### 流水线寄存器

各级之间插入流水线寄存器来传递中间结果：

```
IF/ID → ID/EX → EX/MEM → MEM/WB
```

### 经典例题

**题目**：非流水线 CPU 每条指令 10ns，5 级流水线每级 2ns（含寄存器延迟）。执行 1000 条指令，流水线加速比是多少？

**解答**：
```
非流水线时间 = 1000 × 10ns = 10000ns
流水线第一条指令 = 5 × 2ns = 10ns
之后每 2ns 完成一条
流水线总时间 = 10 + (1000-1) × 2 = 2008ns
加速比 = 10000 / 2008 ≈ 4.98
```

## 2. 流水线冒险（相关性分析）

### 知识点讲解

**冒险（Hazard）** 是指流水线中下一条指令无法在下一个时钟周期正确执行的情况。冒险分为三类：

> **通俗理解**：流水线冒险就像厨房流水线中——厨师需要等锅（结构冒险）、等食材（数据冒险）、或者不知道该做什么菜（控制冒险）。

### 2.1 结构冒险（Structural Hazard）

**原因**：硬件资源冲突，两条指令同时需要使用同一部件。

**例子**：冯·诺依曼结构中，指令取指和访存同时进行会冲突。

**解决方法**：
- 哈佛架构（分离指令 Cache 和数据 Cache）
- 插入气泡（停顿一个周期）

### 2.2 数据冒险（Data Hazard）

**原因**：指令之间存在数据依赖关系。

**三种数据冒险**：

| 类型 | 全称 | 说明 | MIPS 流水线中是否存在 |
|------|------|------|---------------------|
| **RAW** | Read After Write | 后一条读前一条写的结果 | ✅ 存在 |
| **WAW** | Write After Write | 两条指令写同一个寄存器 | ❌ MIPS 5级不存在 |
| **WAR** | Write After Read | 后一条写前一条读的寄存器 | ❌ MIPS 5级不存在 |

> MIPS 五级流水线中，**只有 RAW 冒险需要处理**。

**RAW 冒险示例**：
```assembly
add $s0, $t0, $t1   # 写入 $s0
sub $t2, $s0, $t3   # 读取 $s0 ← RAW 数据冒险！
```

**解决方法**：
1. **转发（Forwarding/Bypassing）**：将计算结果直接从流水线寄存器传给需要它的指令
2. **插入停顿（Stall）**：lw 指令后紧跟使用该结果的指令时，转发不够，需停顿 1 周期
3. **编译器调度**：在 lw 和使用之间插入不相关指令

**转发路径**：
```
EX/MEM → EX：前一条指令的 ALU 结果直接转发
MEM/WB → EX：前两条指令的结果转发
MEM/WB → MEM：用于 sw 指令
```

### 2.3 控制冒险（Control Hazard）

**原因**：分支指令导致不确定下一条指令地址。

**例子**：
```assembly
beq $t0, $t1, Target  # EX 阶段才算出是否跳转
                       # 已经多取了 2 条指令！
```

**解决方法**：

| 方法 | 说明 |
|------|------|
| **插入停顿** | 等分支结果出来再取指，每分支损失 2 周期 |
| **预测不跳转** | 假设分支不跳，顺序执行，猜错则冲刷流水线 |
| **预测跳转** | 假设分支跳转 |
| **延迟分支** | 在分支指令后放一条总是执行的指令 |
| **动态预测** | 用历史信息预测 |

### 经典例题

**题目**：识别以下代码中的数据冒险，并说明哪些可以通过转发解决，哪些需要停顿。

```assembly
lw  $t0, 0($s0)
add $t1, $t0, $s1
sub $t2, $t1, $s2
```

**解答**：
```
lw → add：需要 $t0
  lw 在 MEM 阶段才拿到数据
  add 在 EX 阶段就需要 $t0
  → 可以通过从 MEM/WB 转发到 EX 解决
  → 但需要停顿 1 周期（加载-使用冒险）

add → sub：需要 $t1
  add 在 EX 阶段算出结果
  sub 在 EX 阶段就需要 $t1
  → 可以通过从 EX/MEM 转发到 EX 解决
  → 不需要停顿
```

## 3. 记分牌调度技术

### 知识点讲解

**记分牌（Scoreboarding）** 是一种**动态调度**技术，允许指令**乱序执行**，同时保证正确性。最早在 CDC 6600 超级计算机中实现。

> **通俗理解**：记分牌就像一个"交通调度中心"——它跟踪所有正在执行的指令，知道每条指令什么时候需要什么资源，能提前准备好的就先执行，解决数据依赖导致的流水线停顿。

### 3.1 为什么需要动态调度

静态调度由编译器负责，但：
- 编译器不知道运行时延迟（如 Cache 缺失）
- 编译器无法预知分支结果
- 不同的程序有不同的数据依赖模式

动态调度由硬件在运行时解决这些问题。

### 3.2 记分牌的基本思想

记分牌维护三个表来跟踪指令执行状态：

| 表名 | 作用 |
|------|------|
| **指令状态表（Instruction Status）** | 记录每条指令当前处于哪个阶段 |
| **功能部件状态表（Functional Unit Status）** | 记录每个功能部件的忙/闲状态 |
| **寄存器结果状态表（Register Result Status）** | 记录哪个功能部件将写入哪个寄存器 |

### 3.3 记分牌的四个阶段

| 阶段 | 英文 | 说明 |
|------|------|------|
| **发射（Issue）** | Issue | 检查结构冒险（功能部件是否空闲），发射指令 |
| **读操作数（Read Operands）** | Read Operands | 检查 RAW 冒险（源寄存器是否就绪），等待直到可读 |
| **执行（Execute）** | Execute | 执行运算，完成后通知记分牌 |
| **写结果（Write Result）** | Write Result | 检查 WAR 冒险（是否有后续指令要读此寄存器），等待后写回 |

### 3.4 三种冒险在记分牌中的处理

| 冒险类型 | 在哪一阶段检测 | 如何处理 |
|----------|--------------|----------|
| **结构冒险** | Issue | 功能部件忙 → 停顿发射 |
| **RAW** | Read Operands | 源寄存器未就绪 → 等待 |
| **WAR** | Write Result | 有后续指令未读此寄存器 → 等待写回 |

### 3.5 记分牌的局限性

| 局限性 | 说明 |
|--------|------|
| **没有寄存器重命名** | WAR 和 WAW 靠等待解决，限制性能 |
| **功能部件数量有限** | 结构冒险限制并行度 |
| **集中式控制** | 所有指令的状态更新由记分牌统一管理 |

### 经典例题

**题目**：用记分牌执行以下代码，分析 RAW 冒险的处理。

```assembly
MUL.D  F0, F2, F4
ADD.D  F6, F0, F8
SUB.D  F10, F6, F12
```

**解答**：
```
MUL.D 发射 → 乘法器忙，开始执行（乘法多周期）
ADD.D 发射 → 进入读操作数阶段
  → F0 未就绪（MUL.D 还没写完）
  → ADD.D 停顿在 Read Operands 阶段

MUL.D 执行完毕 → 写结果（检查 WAR 无冲突）→ F0 就绪
ADD.D 检测到 F0 就绪 → 读操作数 → 执行 → 写结果
SUB.D 类似地等待 F6
```

## 4. Tomasulo 调度技术

### 知识点讲解

**Tomasulo 算法** 是由 IBM 在 360/91 上提出的动态调度算法，相比记分牌增加了**寄存器重命名**和**保留站**，能更有效地解决 WAR 和 WAW 冒险。

> **通俗理解**：Tomasulo 比记分牌聪明的地方在于——它不只是"等"，而是给数据起"标签"（Tag）。谁产生这个数据就用标签标记，需要数据的指令认标签不认寄存器名，这样就不会因为寄存器名相同而误等。

### 4.1 Tomasulo 的核心组件

| 组件 | 作用 |
|------|------|
| **保留站（Reservation Stations）** | 每个功能部件前有多个保留站，存放等待发射的指令和操作数 |
| **寄存器别名表（Register Alias Table, RAT）** | 记录每个寄存器当前被哪个保留站"预订"了 |
| **公共数据总线（Common Data Bus, CDB）** | 所有功能部件通过 CDB 广播结果，所有等待的部件同时接收 |
| **加载/存储缓冲（Load/Store Buffer）** | 处理内存访问的保留站 |

### 4.2 Tomasulo 的三个阶段

| 阶段 | 说明 |
|------|------|
| **发射（Issue）** | 从指令队列取出指令，检查保留站是否空闲（结构冒险） |
| | 如果源操作数在寄存器中就读取，否则记下哪个保留站会产生它 |
| | 将寄存器重命名为保留站标签 → **消除 WAR/WAW** |
| **执行（Execute）** | 操作数就绪后开始执行（通过 CDB 接收结果） |
| | 多个周期可同时监控 CDB |
| **写结果（Write Result）** | 将结果放到 CDB 上广播 |
| | 所有等待此结果的保留站和寄存器同时更新 |

### 4.3 Tomasulo vs 记分牌

| 特性 | 记分牌 | Tomasulo |
|------|--------|----------|
| **寄存器重命名** | ❌ 没有 | ✅ 有（通过保留站标签） |
| **WAR/WAW 处理** | 靠等待（写结果时检查） | 靠重命名（发射时消除） |
| **结果广播** | 逐一传递 | CDB 广播，同时到达 |
| **控制方式** | 集中式 | 分布式（保留站各自监控 CDB） |
| **硬件复杂度** | 低 | 高 |

### 4.4 Tomasulo 的执行示例

```assembly
MUL.D  F0, F2, F4
ADD.D  F6, F0, F8
SUB.D  F10, F6, F12
```

**执行过程**：

```
发射 MUL.D：分配保留站 RS1，F0 → RS1 的 Tag
发射 ADD.D：分配保留站 RS2
  → F0 的 Tag = RS1（不是等，而是记下谁会产生这个值）
  → 消除 WAR（后续指令写 F0 也不影响 ADD.D）

MUL.D 执行完 → CDB 广播结果
  → RS2 收到 RS1 的结果 → F0 就绪
  → ADD.D 开始执行

发射 SUB.D：分配保留站 RS3
  → F6 的 Tag = RS2

ADD.D 执行完 → CDB 广播结果
  → RS3 收到 RS2 的结果 → F6 就绪
  → SUB.D 开始执行
```

### 4.5 加载/存储的处理

Tomasulo 通过**加载/存储缓冲**处理内存访问：
- 加载指令需要计算地址，然后从内存加载
- 存储指令需要等待数据就绪，然后写入内存
- **内存别名检测**：确保不同地址的加载/存储不乱序

### 经典例题

**题目**：Tomasulo 如何解决以下代码中的 WAR 冒险？

```assembly
ADD.D  F0, F2, F4      # 写 F0
SUB.D  F4, F6, F8      # 写 F4，读 F0 在后面？
```

**解答**：
```
在记分牌中，ADD.D 和 SUB.D 存在 WAR（SUB.D 写 F4，但 ADD.D 可能在读 F4？不，这里实际上是 WAW）

在 Tomasulo 中：
1. ADD.D 发射 → 保留站 RS1 → RAT 记录 F0=RS1
2. SUB.D 发射 → 保留站 RS2 → RAT 记录 F4=RS2
   → F6, F8 从寄存器读（如果就绪）
   → 没有问题！因为 F0 和 F4 是不同的寄存器

假设代码改为：
MUL.D  F0, F2, F4      # 写 F0
ADD.D  F6, F0, F8      # 读 F0（RAW）
MUL.D  F0, F10, F12    # 又写 F0（WAW with 第一条）

Tomasulo 处理：
1. 第一条 MUL.D → RS1，RAT[F0]=RS1
2. ADD.D → RS2，源操作数 F0 的 Tag=RS1
3. 第二条 MUL.D → RS3，RAT[F0]=RS3（覆盖）
   → ADD.D 已经在 RS2 中记录了 RS1 的 Tag
   → ADD.D 仍然等待第一条的结果 → WAW 被消除！
```

## 5. 分支预测技术

### 知识点讲解

**分支预测（Branch Prediction）** 用于解决控制冒险——在分支结果算出来之前预测跳转方向，并根据预测取指令执行。

> **通俗理解**：就像你在路上遇到岔路口——你不能停下来等导航，必须猜一个方向先走。猜对了省时间，猜错了走回头路（冲刷流水线）。

### 5.1 分支预测的重要性

理想流水线 CPI = 1，但每 5~6 条指令就有一条分支。如果没有预测：
- 每遇到分支就停顿 2~3 周期
- CPI 增加到 1.3~1.5
- 性能损失 30%~50%

### 5.2 静态分支预测

| 策略 | 准确率 | 说明 |
|------|--------|------|
| **预测不跳转** | ~60% | 总是顺序执行，简单但准确率低 |
| **预测跳转** | ~40% | 总是跳转 |
| **反向跳转预测为跳转** | ~85% | 循环末端的向后跳转（循环通常执行多次） |

### 5.3 动态分支预测

#### 1 位预测器

使用 1 位历史位记录上次该分支是否跳转：

```
            跳转                         不跳转
预测不跳转 ───────→ 预测跳转   预测跳转 ────────→ 预测不跳转
         ←───────              ←────────
         不跳转                      跳转
```

**问题**：内层循环最后退出时会预测错两次（一次退出、一次重新进入）。

#### 2 位预测器

使用 2 位状态机，需要连续猜错 **两次** 才改变预测：

```
状态 00：强不跳转
状态 01：弱不跳转
状态 10：弱跳转
状态 11：强跳转

规则：猜错一次 → 改变到相邻状态
      猜对两次 → 回到强状态
```

**准确率**：>90%（对频繁执行的分支）

#### 分支历史表（BHT）

- 用分支指令地址的低位作为索引
- 每个表项存 2 位预测值
- 无需知道分支指令的地址就能预测

#### 相关预测器（Correlating Predictor）

使用**全局历史** + **局部历史** 共同预测：
- 2 位全局历史记录最近两次分支的结果
- 结合分支地址索引到不同的 2 位预测器
- 准确率更高（>95%）

### 5.4 分支目标缓冲器（BTB）

除了预测是否跳转，还需要知道**跳到哪里**。

BTB 是一个 Cache，存储：

| 字段 | 说明 |
|------|------|
| **分支指令地址** | 作为索引 |
| **预测目标地址** | 跳转的目标地址 |
| **预测位** | 2 位预测信息 |

**工作原理**：
```
IF 阶段：用 PC 查 BTB
  命中且预测跳转 → 直接取出目标地址 → 下周期从目标取指
  命中且预测不跳转 → 顺序执行
  未命中 → 顺序执行
```

### 5.5 分支预测失败的开销

```
预测错误代价 = 流水线级数 - 1（从分支指令到算出结果的级数）

MIPS 5 级流水线中，分支在 EX 阶段确定：
→ 错误预测代价 = 2 周期（IF 阶段已取 2 条指令需要冲刷）
```

### 5.6 推测执行（Speculative Execution）

- 根据预测结果，推测性地取指、执行
- 结果不立即提交（commit），而是放在重排序缓冲（ROB）中
- 预测正确 → 提交结果
- 预测错误 → 废弃推测执行的所有结果，恢复现场

### 5.7 混合预测器（Hybrid Predictor）

结合多种预测器，用选择器选择最准确的一个：

```
分支指令 → 选择器 → 选择预测结果
          ├── 基于 BHT 的预测器
          └── 基于全局历史的预测器
```

现代处理器（如 Intel Core i7）使用两级自适应预测器，准确率 >97%。

### 经典例题

**题目 1**：一个循环执行 10 次。第一次执行时 1 位预测器初始为"预测不跳转"。求总预测准确率。

**解答**：
```
循环 10 次：
第 1 次：预测不跳转 → 实际跳转 → 错误，改为预测跳转
第 2~9 次：预测跳转 → 实际跳转 → 正确（8 次正确）
第 10 次：预测跳转 → 实际不跳转 → 错误

准确率 = 8/10 = 80%
```

**题目 2**：同上，用 2 位预测器（初始为 11=强跳转），准确率多少？

**解答**：
```
初始状态 11（强跳转）
循环 10 次：
第 1 次：预测跳转 → 实际跳转 → 正确，状态 11
第 2 次：预测跳转 → 实际跳转 → 正确，状态 11
...
第 9 次：预测跳转 → 实际跳转 → 正确，状态 11
第 10 次：预测跳转 → 实际不跳转 → 错误，状态 10（弱跳转）

退出循环后：
下一分支指令：预测跳转 → 实际不跳转 → 错误，状态 01

准确率（10 次循环）= 9/10 = 90%（1 位预测器是 80%）
```
