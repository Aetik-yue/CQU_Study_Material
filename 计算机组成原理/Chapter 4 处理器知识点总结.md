## 1. 处理器的基本概念

### 知识点讲解

**处理器（Processor / CPU）** 是计算机的"大脑"，它的核心任务是**执行指令**。每条指令的执行可以分解为以下几个基本步骤：

> **通俗理解**：处理器就像一个工厂的流水线工人——他需要"取材料（取指令）→ 看图纸（译码）→ 加工（执行）→ 写报告（写回）"。

### 指令执行的五个阶段

| 阶段 | 英文 | 说明 | 比喻 |
|------|------|------|------|
| **IF** | Instruction Fetch | 从内存中取出指令 | 工人从架子上拿图纸 |
| **ID** | Instruction Decode | 解析指令，读取寄存器 | 工人看懂图纸，准备材料 |
| **EX** | Execution | 执行运算或计算地址 | 工人进行实际加工 |
| **MEM** | Memory Access | 访问内存（lw/sw） | 工人去仓库取/放东西 |
| **WB** | Write Back | 将结果写回寄存器 | 工人在记录本上登记 |

### 两种基本设计方法

| 设计 | 特点 | 类比 |
|------|------|------|
| **单周期实现** | 每条指令在一个时钟周期内完成 | 一个人一次做一道菜，做完再做下一道 |
| **流水线实现** | 多条指令重叠执行 | 厨房流水线：洗菜、切菜、炒菜同时进行 |

### 关键术语

| 术语 | 说明 |
|------|------|
| **时钟周期 (Clock Cycle)** | CPU 工作的基本时间单位 |
| **CPI** | Cycles Per Instruction（每条指令平均周期数） |
| **吞吐量 (Throughput)** | 单位时间内完成的指令数 |
| **延迟 (Latency)** | 完成一条指令所需的时间 |

## 2. 数据通路（Datapath）

### 知识点讲解

**数据通路**是处理器中用于**处理数据**的部件及其连接方式。它包括：
- 算术逻辑单元（ALU）
- 寄存器堆（Register File）
- 数据存储器（Data Memory）
- 指令存储器（Instruction Memory）
- 各种多路选择器（MUX）

> **通俗理解**：数据通路就是处理器内部的"高速公路网络"，数据在这条路上从寄存器到 ALU，再到内存，最后再回来。

### 核心组件

| 组件 | 功能 |
|------|------|
| **PC（程序计数器）** | 存放下一条要执行指令的地址 |
| **指令存储器** | 存储程序的所有指令 |
| **寄存器堆** | 32 个通用寄存器 |
| **ALU** | 执行算术和逻辑运算 |
| **数据存储器** | 存储数据（内存） |
| **加法器** | 专门用来计算 PC+4 和分支目标地址 |

### 经典例题

**题目**：画出 MIPS `lw` 指令在数据通路中的执行路径。

**解答**：

```
PC → 指令存储器 → 寄存器堆（读rs） → ALU（计算地址） → 数据存储器 → 寄存器堆（写回）
                          ↑（读rt）
```

`lw` 指令经过的组件：
1. PC → 指令存储器（取指令）
2. 指令 → 寄存器堆（读取基址寄存器 rs）
3. rs 的值 + 立即数偏移 → ALU（计算内存地址）
4. ALU 结果 → 数据存储器（读取数据）
5. 数据 → 寄存器堆（写回到 rt）

## 3. 控制单元（Control Unit）

### 知识点讲解

**控制单元**负责根据指令的类型，生成控制信号来指挥数据通路中的各个组件工作。

> **通俗理解**：控制单元就像"交通指挥员"——它告诉每个 MUX 走哪条路，告诉 ALU 做什么运算，告诉存储器是读还是写。

### 主要控制信号

| 控制信号 | 说明 | 取值 |
|----------|------|------|
| **RegDst** | 选择写回寄存器的地址（rd 还是 rt） | 0=rt, 1=rd |
| **ALUSrc** | ALU 第二个操作数来自寄存器还是立即数 | 0=寄存器, 1=立即数 |
| **MemtoReg** | 写回寄存器的数据来自 ALU 还是内存 | 0=ALU, 1=内存 |
| **RegWrite** | 是否写寄存器 | 0=不写, 1=写 |
| **MemRead** | 是否读内存 | 0=不读, 1=读 |
| **MemWrite** | 是否写内存 | 0=不写, 1=写 |
| **Branch** | 是否是分支指令 | 0=否, 1=是 |
| **ALUOp** | ALU 操作类型 | 2位编码 |

### 各类指令的控制信号

| 指令 | RegDst | ALUSrc | MemtoReg | RegWrite | MemRead | MemWrite | Branch |
|------|--------|--------|----------|----------|---------|----------|--------|
| R-type | 1 | 0 | 0 | 1 | 0 | 0 | 0 |
| lw | 0 | 1 | 1 | 1 | 1 | 0 | 0 |
| sw | X | 1 | X | 0 | 0 | 1 | 0 |
| beq | X | 0 | X | 0 | 0 | 0 | 1 |

> X = 不关心（Don't Care）

### 经典例题

**题目**：如果控制信号 ALUSrc 被错误地设为 0（应为 1），`lw $t0, 40($s0)` 会怎样执行？

**解答**：
- ALUSrc = 0 意味着 ALU 的第二个操作数来自**寄存器**（rt）而不是**立即数**
- 所以 ALU 会计算 `$s0 + $t0`（$t0 的内容）而不是 `$s0 + 40`
- 得到的内存地址是错的，会加载错误的数据
- 这就是为什么控制信号必须正确的关键！

## 4. 单周期处理器

### 知识点讲解

**单周期处理器**是指所有指令都在**一个时钟周期**内完成。每个周期内，指令依次经过 IF → ID → EX → MEM → WB 所有阶段。

> **通俗理解**：就像食堂只有一个打饭窗口——每个人都要从头到尾打完饭才能轮到下一个人。简单但慢。

### 设计要点

- **时钟周期必须足够长**，以容纳最慢的指令（通常是 `lw`）
- 所有指令都在一个周期内完成
- 硬件设计简单，但效率低

### 关键路径（Critical Path）

最慢的指令决定了时钟周期长度。`lw` 通常是最慢的，因为它经过的组件最多：

```
PC → 指令存储器 → 寄存器堆(读) → ALU → 数据存储器(读) → 寄存器堆(写)
```

### 单周期 vs 其他设计

| 指标 | 单周期 | 多周期 | 流水线 |
|------|--------|--------|--------|
| 时钟周期 | 长（50ns） | 中等（10ns） | 短（10ns） |
| CPI | 1 | 3~5 | 1（理想） |
| 吞吐量 | 低 | 中 | 高 |
| 硬件复杂度 | 低 | 中 | 高 |

### 经典例题

**题目**：假设：
- 指令存储器：2ns
- 寄存器堆读写：1ns
- ALU：2ns
- 数据存储器读写：2ns
- 控制单元等开销：0.5ns

求单周期处理器的最大时钟频率。

**解答**：
最慢指令是 `lw`，经过的路径：
```
IF(2ns) + ID(1ns) + EX(2ns) + MEM(2ns) + WB(1ns) + 控制(0.5ns)
= 2 + 1 + 2 + 2 + 1 + 0.5 = 8.5ns
```

最大时钟频率 = 1 / 8.5ns ≈ 117.6 MHz

## 5. 流水线（Pipeline）概述

### 知识点讲解

**流水线**是提高处理器吞吐量的核心技术。它将指令执行过程分成多个阶段，**不同指令的不同阶段可以重叠执行**。

> **通俗理解**：就像洗衣服——你不需要等洗完晾干再洗下一批。你可以同时洗一批、甩干一批、晾一批。流水线让处理器的"各个功能部件"一直忙碌，而不是等待一条指令完全结束才开始下一条。

### 五级流水线

| 阶段 | 功能 |
|------|------|
| **IF** | 取指令（Fetch） |
| **ID** | 译码、读寄存器（Decode） |
| **EX** | 执行、计算地址（Execute） |
| **MEM** | 访存（Memory） |
| **WB** | 写回寄存器（Write Back） |

### 流水线的性能

**理想情况下**，流水线将吞吐量提高到原来的 **N 倍**（N = 流水线级数）。

```
非流水线：   [IF][ID][EX][MEM][WB]  [IF][ID][EX][MEM][WB]  ...
                    ↑ 一条指令完成才取下一条

流水线：     [IF][ID][EX][MEM][WB]
               [IF][ID][EX][MEM][WB]
                  [IF][ID][EX][MEM][WB]
                    ↑ 每周期完成一条指令！
```

### 流水线加速比

- **理想加速比** = 流水线级数（5 级流水线理想快 5 倍）
- **实际加速比** < 理想值，因为存在**冒险（Hazards）**

### 经典例题

**题目**：一段程序有 1000 条指令。非流水线 CPU 每条指令 10ns。5 级流水线 CPU 每级 2ns。不考虑冒险，各需要多少时间？

**解答**：

- **非流水线**：1000 × 10ns = **10000ns**
- **流水线（理想）**：
  - 第一条指令需要：5 × 2ns = 10ns
  - 之后每 2ns 完成一条
  - 总时间 = 10ns + (1000-1) × 2ns = **2008ns**
- **加速比** = 10000 / 2008 ≈ **4.98 倍**

## 6. 流水线数据通路

### 知识点讲解

为了实现流水线，我们需要在每两个阶段之间插入**流水线寄存器（Pipeline Registers）**，用来保存中间结果。

> **通俗理解**：流水线寄存器就像流水线上每个工位之间的"传送带"——工人把半成品放在传送带上，下一个工人拿起来继续加工。

### 五级流水线的流水线寄存器

| 寄存器 | 位置 | 保存的内容 |
|--------|------|-----------|
| **IF/ID** | IF 和 ID 之间 | 取到的指令、PC+4 |
| **ID/EX** | ID 和 EX 之间 | 控制信号、读取的寄存器值、立即数扩展值、rt/rd编号 |
| **EX/MEM** | EX 和 MEM 之间 | ALU 结果、分支目标地址、写入数据、rt编号 |
| **MEM/WB** | MEM 和 WB 之间 | 从内存读取的数据、ALU 结果、写入寄存器编号 |

### 控制信号的流水线传递

控制信号在 ID 阶段生成后，会随着流水线寄存器逐级传递：

```
ID阶段生成 → ID/EX → EX/MEM → MEM/WB
```

- **EX 阶段使用的信号**：ALUSrc, ALUOp, RegDst
- **MEM 阶段使用的信号**：MemRead, MemWrite, Branch
- **WB 阶段使用的信号**：MemtoReg, RegWrite

## 7. 流水线冒险（Hazards）

### 知识点讲解

**冒险**是指流水线中下一条指令无法在下一个时钟周期正确执行的情况。有三种类型的冒险：

> **通俗理解**：就像厨房流水线上——如果厨师 A 需要等厨师 B 用完锅才能炒菜（结构冒险），或者需要等厨师 B 切完菜才能用（数据冒险），或者接到菜单发现不知道做什么菜（控制冒险）。

---

### 7.1 结构冒险（Structural Hazard）

#### 知识点讲解

**结构冒险**发生在硬件资源不足时——两条指令同时需要使用同一个硬件部件。

#### 举例

```
lw  $t0, 0($sp)    [IF] [ID] [EX] [MEM] [WB]
add $t1, $t0, $s0        [IF] [ID] [EX] [MEM] [WB]
```

如果指令存储器和数据存储器是同一个（冯·诺依曼架构），那么第一条指令在 MEM 阶段访问内存时，第二条指令在 IF 阶段也要访问内存——**冲突！**

#### 解决方法

| 方法 | 说明 |
|------|------|
| **哈佛架构** | 分开的指令缓存和数据缓存（MIPS 采用） |
| **插入气泡** | 暂停一条指令，插入一个空操作 |

> 现代处理器大多使用分离的缓存（L1 I-Cache 和 L1 D-Cache）来避免结构冒险。

#### 经典例题

**题目**：冯·诺依曼架构的处理器，如果在同一周期既要取指令又要访问数据，会发生什么？

**解答**：
- 会发生**结构冒险**——内存同一时间只能响应一个请求
- 解决方法：插入一个**停顿（stall）** 周期，让取指令等一等
- 代价是性能损失

---

### 7.2 数据冒险（Data Hazard）

#### 知识点讲解

**数据冒险**是指一条指令依赖于前一条指令的结果，但前一条指令的结果还没写回寄存器。

> **通俗理解**：你要用面粉，但面粉还在加工中没出来——你只能等着。

#### 三种数据冒险类型

| 类型 | 名称 | 说明 | 示例 |
|------|------|------|------|
| **RAW** | 读后写 | 后一条指令读前一条的结果 | `add $t0,...` 后面用 `$t0` |
| **WAW** | 写后写 | 两条指令写同一个寄存器（MIPS 5级流水线不存在） | 较少见 |
| **WAR** | 写后读 | 后一条指令写，前一条读（MIPS 不存在） | 较少见 |

> MIPS 五级流水线中只存在 RAW 冒险。

#### 数据冒险检测

通过检查流水线寄存器中的目标寄存器编号和当前指令的源寄存器编号是否匹配：

```assembly
add $s0, $t0, $t1   # 写入 $s0
sub $t2, $s0, $t3   # 读取 $s0 ← 数据冒险！
```

#### 经典例题

**题目**：指出以下代码中的数据冒险：

```assembly
lw  $t0, 0($s0)
add $t1, $t0, $s1
sub $t2, $t1, $s2
```

**解答**：
1. **lw → add**：add 需要 $t0，但 lw 要到 WB 阶段才把数据写回 $t0
2. **add → sub**：sub 需要 $t1，但 add 要到 WB 阶段才写回 $t1

这涉及两种解决方案：**转发** 和 **插入气泡**（见第 8、9 节）。

---

### 7.3 控制冒险（Control Hazard）

#### 知识点讲解

**控制冒险**（也叫分支冒险）发生在执行分支指令时——我们不知道下一条该取哪条指令，因为分支结果还没算出来。

> **通俗理解**：开车到了一个岔路口，你还没决定左转还是右转，但车不能停——你必须猜一个方向先走。

#### 分支指令的时间线

```
beq $t0, $t1, Target  [IF] [ID] [EX] [MEM] [WB]
?                     [IF] [ID] [EX] [MEM] [WB]   ← 取哪条指令？
```

beq 在 EX 阶段才算出结果，这意味着我们**已经多取了 2 条指令**。

#### 解决方法

| 方法 | 说明 | 性能损失 |
|------|------|----------|
| **插入停顿** | 等到分支结果出来再取下一条 | 每分支损失 2 个周期 |
| **预测不跳转** | 假设分支不跳，继续顺序执行 | 猜对 0 损失，猜错 2 损失 |
| **预测跳转** | 假设分支跳转 | 同上 |
| **动态预测** | 根据历史记录预测 | 猜对率高 |

## 8. 转发（Forwarding）技术

### 知识点讲解

**转发**（也叫旁路 Bypassing）是解决数据冒险最有效的方法。它的思路是：**结果一算出来就传给需要的指令，不等它写回寄存器**。

> **通俗理解**：你在做菜，A 刚切好葱花，B 马上要葱花——A 直接递过去，不用先放回冰箱再拿出来。

### 转发的工作原理

```
add $s0, $t0, $t1    [IF] [ID] [EX] [MEM] [WB]
sub $t2, $s0, $t3         [IF] [ID] [EX] [MEM] [WB]
                              ↑转发 $s0 的结果！
```

add 在 EX 阶段就算出了 $s0 的结果，这个结果可以直接从 EX/MEM 流水线寄存器转发给 sub 的 EX 阶段。

### 转发路径

| 转发源 | 目标 | 说明 |
|--------|------|------|
| **EX/MEM** → **EX** | EX 阶段 | 前一条指令的结果直接传给 ALU 输入 |
| **MEM/WB** → **EX** | EX 阶段 | 前两条指令的结果传给 ALU 输入 |
| **MEM/WB** → **MEM** | MEM 阶段 | 用于 sw 指令 |

### 需要转发的指令组合

```assembly
# 情况 1：EX/MEM → EX（前一条的结果在 EX/MEM 中）
add $s0, $t0, $t1    # EX 阶段产出结果
sub $t2, $s0, $t3    # 下一条指令的 EX 阶段需要 $s0

# 情况 2：MEM/WB → EX（前两条的结果在 MEM/WB 中）
add $s0, $t0, $t1
nop                   # 或一条不相关的指令
sub $t2, $s0, $t3    # 从 MEM/WB 转发
```

### 经典例题

**题目**：以下代码中，转发能否解决所有数据冒险？如果不能，如何处理？

```assembly
lw  $t0, 0($s0)
add $t1, $t0, $s1
```

**解答**：
- `lw` 在 MEM 阶段才拿到数据（从内存读取）
- `add` 在 EX 阶段就需要 $t0
- 转发路径：MEM（lw 的 MEM 阶段）→ EX（add 的 EX 阶段）
- **可以转发！** 从 MEM/WB 寄存器转发到 add 的 ALU 输入

但是如果是：
```assembly
lw  $t0, 0($s0)
sw  $t0, 0($s1)
```
- `lw` 在 MEM 阶段拿到数据
- `sw` 在 MEM 阶段需要 $t0 作为写入数据
- 转发路径：MEM → MEM（从 lw 的 MEM 阶段直接给 sw 的 MEM 阶段）
- **需要"加载-使用"检测**——这就是为什么有些情况仍需停顿

## 9. 流水线停顿与插入气泡

### 知识点讲解

虽然转发能解决大部分数据冒险，但有一种情况转发解决不了——**加载-使用冒险（Load-Use Hazard）**。当 `lw` 指令加载的数据立即被下一条指令使用时，需要插入一个**气泡（Bubble）** 即停顿周期。

> **通俗理解**：有些材料没法直接传递——比如你要用刚从仓库领出来的零件。仓库那边刚拿出来还在路上，你就只能等一个节拍。

### 什么时候需要停顿

```assembly
lw  $t0, 0($s0)      # MEM 阶段才拿到数据
add $t1, $t0, $s1    # EX 阶段就需要 $t0 → 需要停顿！
```

停顿后的流水线：

```
lw  [IF] [ID] [EX] [MEM] [WB]
add      [IF] [ID] [STALL] [EX] [MEM] [WB]
                                      ↑ 插入一个气泡
```

### 硬件检测单元

处理器中有一个**冒险检测单元（Hazard Detection Unit）** 负责：
1. 检查 ID/EX 中的 rt 是否等于 IF/ID 中的 rs 或 rt（即 lw 的目标是否是下一条指令的源）
2. 如果是，将 ID/EX 的控制信号全部清零（插入气泡）
3. 同时让 PC 和 IF/ID 寄存器保持不变（停顿）

### 编译器优化

优秀的编译器可以通过**指令调度（Instruction Scheduling）** 来避免加载-使用冒险：

```assembly
# 不好的代码：lw 后立即使用
lw  $t0, 0($s0)
add $t1, $t0, $s1    # 需要停顿

# 好的代码：在 lw 和它的使用之间插入其他指令
lw  $t0, 0($s0)
add $s2, $s3, $s4    # 不相关的指令
add $t1, $t0, $s1    # 不再需要停顿
```

### 经典例题

**题目**：以下代码需要插入几个停顿周期？

```assembly
lw  $t0, 0($s0)
add $t1, $t0, $s1
sub $t2, $t1, $s2
```

**解答**：

```
# 分析冒险：
# lw → add: $t0 有加载-使用冒险 → 需要 1 个停顿
# add → sub: $t1 可以通过转发解决 → 不需要停顿

# 停顿后流水线：
lw   [IF] [ID] [EX] [MEM] [WB]
add       [IF] [ID] [STL] [EX] [MEM] [WB]  ← $t0 从 MEM/WB 转发到 EX
sub            [IF] [IF]  [ID] [EX] [MEM]  ← $t1 从 EX/MEM 转发到 EX
```

所以只需要 **1 个停顿周期**。

## 10. 分支预测

### 知识点讲解

**分支预测**用于解决控制冒险——在分支结果算出来之前，猜测分支是否跳转，并根据猜测取指令。

> **通俗理解**：就像天气预测——你猜明天会不会下雨来决定带不带伞。猜对了方便，猜错了麻烦。

### 静态分支预测

| 策略 | 说明 | 准确率 |
|------|------|--------|
| **预测不跳转** | 总是假设分支不跳转 | ~60% |
| **预测跳转** | 总是假设分支跳转 | ~40% |
| **反向跳转预测为跳转** | 循环末尾的向后跳转通常发生 | 用于循环 |

### 动态分支预测

**分支历史表（Branch History Table, BHT）**：记录每个分支指令的历史行为。

#### 1 位预测器

| 状态 | 跳转？ | 下次预测 |
|------|--------|----------|
| 预测不跳转 | 不跳转 → 预测正确 | 仍预测不跳转 |
| 预测不跳转 | 跳转 → 预测错误 | 改为预测跳转 |
| 预测跳转 | 跳转 → 预测正确 | 仍预测跳转 |
| 预测跳转 | 不跳转 → 预测错误 | 改为预测不跳转 |

#### 2 位预测器

使用 2 位状态机，需要连续猜错**两次**才改变预测方向。准确率更高（~90%+）。

```
          猜错1次              猜错1次
预测不跳转 ←————→ 弱不跳转 ←————→ 弱跳转 ←————→ 预测跳转
                 猜对恢复            猜对恢复
```

### 分支目标缓冲器（BTB）

除了预测是否跳转，还要知道**跳到哪里**。BTB 缓存分支指令的地址和对应的目标地址。

### 经典例题

**题目**：一个循环执行 10 次，使用 1 位预测器。第一次执行循环时预测不跳转，问预测准确率。

**解答**：
- 前 9 次循环：执行到末尾，分支**跳转**回循环开始
  - 第 1 次：预测不跳转 → 实际跳转 → 错误（改为预测跳转）
  - 第 2 次：预测跳转 → 实际跳转 → 正确
  - ...
  - 第 9 次：预测跳转 → 实际跳转 → 正确
- 第 10 次：执行到末尾，分支**不跳转**（退出循环）
  - 预测跳转 → 实际不跳转 → 错误

准确率 = (8 次正确) / (10 次) = **80%**

## 11. 异常与中断

### 知识点讲解

**异常（Exception）** 是指 CPU 在执行指令时遇到的意外情况（如溢出、无效指令等）。**中断（Interrupt）** 是外部设备发出的信号。

> **通俗理解**：异常就像你写代码时发现了 bug（除零错误），中断就像你正在工作，电话响了（外部事件）。

### MIPS 中的异常处理

| 组件 | 说明 |
|------|------|
| **Cause 寄存器** | 记录异常原因 |
| **EPC（Exception PC）** | 保存发生异常的指令地址 |
| **异常处理程序** | 处理异常的程序（在操作系统内核中） |

### 流水线中的异常

流水线中处理异常更复杂，因为有多条指令同时执行：

| 问题 | 说明 |
|------|------|
| **精确异常** | 异常发生时，前面的指令已完成，后面的指令还未开始 |
| **不精确异常** | 多条指令都发生了异常，难以确定是哪条导致的 |
| **复杂情况** | 需要保证异常不会破坏程序状态 |

> MIPS 要求**精确异常**——异常发生时，流水线要 flush 异常指令后面的指令，让前面的指令正常完成。

## 12. 指令级并行（ILP）

### 知识点讲解

**指令级并行（Instruction-Level Parallelism）** 是让多条指令同时执行的技术。

> **通俗理解**：不只是流水线让指令重叠执行，还可以通过更"激进"的方式让多条指令真正并行执行。

### ILP 的来源

| 来源 | 说明 | 示例 |
|------|------|------|
| **流水线** | 不同指令在不同阶段重叠 | 基本的五级流水线 |
| **多发射** | 每个周期发射多条指令 | 超标量处理器 |
| **超流水线** | 将流水线分得更细 | 10 级、20 级流水线 |
| **乱序执行** | 不按程序顺序执行指令 | 先执行准备好的指令 |

### 超标量（Superscalar）

每个时钟周期发射 **2 条或更多指令**：

```
周期 1: [IF(inst1)] [IF(inst2)]
周期 2: [ID(inst1)] [ID(inst2)]
周期 3: [EX(inst1)] [EX(inst2)]
```

### 超长指令字（VLIW）

编译器将多条可以并行执行的指令打包成一个"长指令"，由硬件直接并行执行。

### 经典例题

**题目**：假设一个 2 路超标量处理器，每个周期最多发射 2 条指令。以下代码需要多少个周期？

```assembly
lw  $t0, 0($s0)
add $t1, $t1, 1
sub $t2, $t2, 1
sw  $t1, 0($s1)
```

**解答**（假设无数据依赖）：

```
周期 1: lw          + add          (同时发射)
周期 2: sub         + sw           (同时发射)
总周期：2 个周期（非超标量需要 4 个周期）
```

## 13. 多周期处理器 vs 单周期处理器

### 知识点讲解

**多周期处理器**将指令分成多个步骤，每个步骤用一个时钟周期，但不同指令可以使用不同数量的周期。

### 设计对比

| 特征 | 单周期 | 多周期 | 流水线 |
|------|--------|--------|--------|
| 每条指令周期数 | 1 | 3~5 | 1（理想） |
| 时钟周期长度 | 长 | 短 | 短 |
| 硬件利用率 | 低（很多部件闲置） | 高（部件复用） | 高（并行工作） |
| 控制逻辑 | 简单（组合逻辑） | 复杂（状态机） | 复杂 |
| 性能 | 低 | 中 | 高 |

### 多周期处理器的优点

- 可以**复用硬件**（例如：一个 ALU 既用来计算地址，又用来执行运算）
- 不同指令可以用不同周期数（lw 5 个周期，add 4 个周期）
- 时钟周期可以更短（每个周期只做一件事）

### 经典例题

**题目**：一个多周期处理器中，`lw` 需要 5 个周期，`add` 需要 4 个周期，`beq` 需要 3 个周期。一个程序有 100 条 lw、200 条 add、50 条 beq，总周期数和平均 CPI 是多少？

**解答**：

```
总周期数 = 100×5 + 200×4 + 50×3 = 500 + 800 + 150 = 1450 周期
总指令数 = 100 + 200 + 50 = 350 条
平均 CPI = 1450 / 350 ≈ 4.14
```

## 14. 现代处理器技术

### 知识点讲解

现代处理器在流水线的基础上，增加了许多先进技术来进一步提升性能。

### 乱序执行（Out-of-Order Execution）

- 指令不按程序顺序执行，而是**有数据就执行**
- 需要**重排序缓冲（ROB）** 来保证最终结果正确
- 指令的**提交（Commit）** 仍然按序进行

```
程序顺序：  lw $t0 → add $t1,$t0 → sub $t2,$s0 → add $t3,$s1
实际执行：  sub $t2,$s0 → add $t3,$s1 → lw $t0 → add $t1,$t0
             ↑ sub 和 add 不依赖前面的结果，先执行
```

### 寄存器重命名（Register Renaming）

解决 WAR 和 WAW 冒险：

```assembly
# 程序中的指令
add $t0, $s0, $s1
sub $s2, $t0, $s3
add $t0, $s4, $s5    # 和第一条的 $t0 不同！

# 重命名后
add $p1, $s0, $s1    # $t0 → 物理寄存器 $p1
sub $s2, $p1, $s3
add $p2, $s4, $s5    # 这个 $t0 → 不同的物理寄存器 $p2
```

### 推测执行（Speculative Execution）

- 在分支预测的基础上，**推测性地执行分支后的指令**
- 如果预测正确，直接使用结果
- 如果预测错误，**废弃**推测执行的结果

### 同时多线程（SMT / Hyper-Threading）

- 一个物理核心同时执行多个线程
- 利用线程间的不相关性来填补流水线气泡

### 数据冒险转发条件

| 条件 | 转发源 | 转发目标 |
|------|--------|----------|

| EX/MEM.RegWrite & EX/MEM.rd = ID/EX.rt | EX/MEM 的 ALU 结果 | ID/EX 的 ALU 输入 B |
| MEM/WB.RegWrite & MEM/WB.rd = ID/EX.rs | MEM/WB 的结果 | ID/EX 的 ALU 输入 A |
| MEM/WB.RegWrite & MEM/WB.rd = ID/EX.rt | MEM/WB 的结果 | ID/EX 的 ALU 输入 B |

### 需要停顿的情况

```
if (ID/EX.MemRead && (ID/EX.rt == IF/ID.rs || ID/EX.rt == IF/ID.rt)) {
    // lw 的加载-使用冒险 → 插入气泡
}
```
