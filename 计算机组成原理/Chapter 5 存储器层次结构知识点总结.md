## 1. 存储层次结构概述

### 知识点讲解

计算机系统面临一个根本矛盾：我们想要**又快又大又便宜**的存储器，但现实中：
- **快的存储器很贵**（SRAM），容量做不大
- **便宜的存储器很慢**（磁盘），容量大但速度慢

> **通俗理解**：就像你想找一个又大又快的仓库——快的仓库（比如你家冰箱）很小，大的仓库（比如超市仓库）很远很慢。那怎么办？把常用的东西放冰箱，不常用的放大仓库！

### 存储层次结构

```
CPU ←→ L1 Cache ←→ L2 Cache ←→ L3 Cache ←→ 主存(DRAM) ←→ 磁盘
   最快/最小/最贵  →  →  →  →  →  →  最慢/最大/最便宜
```

### 层次结构的关键数据

| 层次 | 访问时间 | 价格/GB | 典型容量 |
|------|---------|---------|----------|
| **SRAM (L1~L3 Cache)** | 0.5ns ~ 2.5ns | $2000~$5000 | 32KB ~ 8MB |
| **DRAM (主存)** | 50ns ~ 70ns | $20~$75 | 4GB ~ 64GB |
| **Flash (SSD)** | 0.1 ~ 2ms | $5~$50 | 256GB ~ 2TB |
| **磁盘 (HDD)** | 5ms ~ 20ms | $0.20~$2 | 1TB ~ 20TB |

### 经典例题

**题目**：为什么我们不直接用大容量的 SRAM 做主存？

**解答**：
```
SRAM 每 GB 成本约 $2000~$5000
DRAM 每 GB 成本约 $20~$75

如果使用 8GB SRAM 做主存：8 × $2000 = $16000
如果使用 8GB DRAM 做主存：8 × $20 = $160

成本相差 100 倍！所以用 SRAM 做 Cache（小容量），用 DRAM 做主存。
```

## 2. 存储器技术

### 知识点讲解

| 技术 | 特点 | 用途 |
|------|------|------|
| **静态随机存储器 SRAM** | 速度快(0.5-2.5ns)，集成度低，功耗较高 | Cache（L1/L2/L3） |
| **动态随机存储器 DRAM** | 速度中等(50-70ns)，集成度高，需刷新 | 主存 |
| **闪存 Flash** | 非易失，速度介于DRAM和磁盘之间 | SSD、U盘 |
| **磁盘 HDD** | 容量大，速度慢，非易失 | 大容量存储 |

### DRAM 的发展

| 代次 | 特点 |
|------|------|
| **SDRAM** | 同步 DRAM，与 CPU 时钟同步 |
| **DDR SDRAM** | 双倍数据率，上升沿和下降沿都传输 |
| **DDR2** | 4 倍外部总线速度 |
| **DDR3/DDR4** | 主流存储器 |
| **EDRAM** | 增强型 DRAM，芯片内集成小容量 SRAM Cache |
| **EDO DRAM** | 扩展数据输出 DRAM，带宽高 |

### DRAM 的刷新

动态 RAM 靠电容存储电荷，电荷会逐渐泄漏，必须**定期刷新**。

> **通俗理解**：就像水桶有微小漏洞，需要定期加水。DRAM 的电容会漏电，需要定期"充电"（刷新）。

#### 三种刷新方式

| 方式 | 描述 | 特点 |
|------|------|------|
| **集中式** | 集中一段时间逐行刷新 | 有死区（无法读写），但适合高速存储器 |
| **分散式** | 每个存储周期前半读写，后半刷新 | 无死区，但系统速度降低 |
| **异步式** | 每隔固定时间刷新一行 | 前两种的折中 |

**计算示例**：1M×1位 DRAM，512×2048 矩阵，刷新周期 8ms
- 行地址 A0~A8（共 9 位），每行 2048 个存储元同时刷新
- 8ms 内进行 512 次刷新
- 异步刷新间隔：8ms ÷ 512 ≈ 15.5μs 刷新一次

### 经典例题

**题目**：某 DRAM 芯片存储阵列为 128×128，存储周期 0.5μs，刷新周期 2ms。求集中式刷新和异步式刷新各自的死区时间。

**解答**：
```
集中式刷新：
- 需要 128 个刷新周期
- 刷新时间 = 128 × 0.5μs = 64μs
- 总周期数 = 2ms ÷ 0.5μs = 4000 个周期
- 死区时间 = 64μs（这期间不能读写）

异步式刷新：
- 刷新间隔 = 2ms ÷ 128 = 15.625μs
- 每 15.625μs 刷新一行
- 无连续死区（每次刷新仅 0.5μs）
```

## 3. Cache 基本概念

### 知识点讲解

**Cache** 是位于 CPU 和主存之间的高速缓冲存储器，利用**局部性原理**来加速数据访问。

> **通俗理解**：Cache 就像你书桌上的常用工具——虽然你的工具箱（主存）里有所有工具，但你不会每次用螺丝刀都跑去工具箱翻一遍，而是把常用的放在桌面上（Cache）。

### 局部性原理

| 类型 | 含义 | 示例 |
|------|------|------|
| **时间局部性** | 刚访问过的数据很可能再次被访问 | 循环中的指令、循环变量 |
| **空间局部性** | 刚访问过的数据附近的数据很可能被访问 | 顺序执行的指令、数组元素 |

### Cache 的基本术语

| 术语 | 含义 |
|------|------|
| **块（Block/Line）** | Cache 与主存之间数据传输的最小单位，可包含多个字 |
| **命中（Hit）** | 要访问的数据在 Cache 中 |
| **命中率（Hit Ratio）** | 命中的次数 ÷ 总访问次数 |
| **缺失（Miss）** | 要访问的数据不在 Cache 中 |
| **缺失率（Miss Ratio）** | 1 - 命中率 |
| **缺失代价（Miss Penalty）** | 从下层存储器取回数据所需的时间 |

### 经典例题

**题目**：程序访问内存 1000 次，其中 Cache 命中 950 次，Cache 命中时间 1ns，缺失代价 100ns。求平均访问时间。

**解答**：
```
命中率 = 950/1000 = 0.95
缺失率 = 1 - 0.95 = 0.05
平均访问时间 = 命中时间 + 缺失率 × 缺失代价
            = 1ns + 0.05 × 100ns
            = 1ns + 5ns
            = 6ns
```

## 4. 直接映射 Cache

### 知识点讲解

**直接映射（Direct Mapped）Cache** 是最简单的 Cache 组织方式——每个主存块只能放在 Cache 中**唯一的一个位置**。

> **通俗理解**：就像图书馆的书架，每本书有固定的位置。找书时直接去那个位置，如果不在那里，说明书不在这个书架上。

### 映射规则

```
Cache 块号 = (主存块地址) mod (Cache 总块数)
```

由于 Cache 总块数是 2 的幂，所以取地址的低位即可。

### Cache 地址划分

```
|  Tag (标记位)  |  Index (索引)  |  Block offset (块内偏移)  |  Byte offset (字节偏移)  |
```

对于一个 32 位字节地址，直接映射 Cache 中：
- **n 位 Index**：2ⁿ 个 Cache 块
- **m 位 Block offset**：每块 2ᵐ 个字（2ᵐ⁺² 字节）
- **Tag** = 32 - (n + m + 2)

### Cache 条目内容

每个 Cache 行包含：
| 字段 | 说明 |
|------|------|
| **Valid Bit（有效位）** | 1=有效，0=无效（初始为0） |
| **Tag（标记位）** | 高地址位，用于判断是否是所需的块 |
| **Data（数据）** | 实际存储的块数据 |

### 容量计算示例

**题目**：16KB 数据的直接映射 Cache，4 字/块，32 位地址。需要多少位？

**解答**：
```
16KB = 4K 字 = 2¹² 字
每块 4 字 → 块数 = 2¹²/4 = 2¹⁰ = 1024 块 → 10 位 Index
每块 4 字 = 16 字节 → 2 位块内偏移，2 位字节偏移
Tag = 32 - (10 + 2 + 2) = 18 位
每块数据 = 4 × 32 = 128 位
每块总位 = 128 + 18 (Tag) + 1 (Valid) = 147 位
总 Cache 大小 = 1024 × 147 = 147 Kbits
```

### 经典例题

**题目**：64 块，16 字节/块的直接映射 Cache。地址 1200 映射到哪个块？

**解答**：
```
块地址 = ⌊字节地址 / 每块字节数⌋
       = ⌊1200 / 16⌋ = 75

Cache 块号 = 块地址 mod Cache 块数
           = 75 mod 64 = 11
```

## 5. 组相联与全相联 Cache

### 知识点讲解

**直接映射**虽然简单，但冲突率较高。**相联度（Associativity）** 越高，映射的灵活性越大，缺失率越低。

### 三种映射方式

| 类型 | 描述 | 比较器数 | 缺失率 |
|------|------|---------|--------|
| **直接映射（1路组相联）** | 一个位置唯一确定 | 1 | 最高 |
| **n 路组相联** | 每个组内有 n 个选择 | n | 中等 |
| **全相联** | 任意位置都可放 | 块数 | 最低 |

### 缺失率对比

64KB D-Cache，16 字/块，SPEC2000：

| 相联度 | 缺失率 |
|--------|--------|
| 1 路（直接映射） | 10.3% |
| 2 路 | 8.6% |
| 4 路 | 8.3% |
| 8 路 | 8.1% |

> 从 1 路到 2 路提升明显，再往上收益递减。

### 替换策略

| 策略 | 描述 | 适用场景 |
|------|------|----------|
| **LRU（最近最少使用）** | 替换最久未使用的块 | 2路/4路简单，高相联度太复杂 |
| **Random（随机）** | 随机选一个替换 | 高相联度时性能接近 LRU |

### 经典例题

**题目**：4 块 Cache，访问序列：0, 8, 0, 6, 8。比较直接映射和 2 路组相联的命中率。

**解答**（PPT 第 38-39 页）：
```
直接映射（0 mod 4 = 0, 6 mod 4 = 2, 8 mod 4 = 0）：
访问 0：缺失 → 放入块0
访问 8：缺失（与0冲突）→ 替换块0
访问 0：缺失（8还在块0）→ 替换块0
访问 6：缺失 → 放入块2
访问 8：缺失 → 替换块0
命中率 = 0/5 = 0%

2路组相联（0 mod 2 = 0, 6 mod 2 = 0, 8 mod 2 = 0）：
访问 0：缺失 → 放入组0
访问 8：缺失 → 放入组0（另一路）
访问 0：命中 ✓
访问 6：缺失 → 替换组0中某个
访问 8：命中 ✓
命中率 = 2/5 = 40%
```

## 6. Cache 性能分析

### 知识点讲解

### 平均访存时间（AMAT）

```
AMAT = 命中时间 + 缺失率 × 缺失代价
```

### CPU 时间公式

```
CPU 时间 = (CPU 执行周期 + 存储器停顿周期) × 时钟周期

存储器停顿周期 = 指令数 × 缺失率 × 缺失代价
```

### Cache 性能示例

| 指标 | 数值 |
|------|------|
| I-Cache 缺失率 | 2% |
| D-Cache 缺失率 | 4% |
| 缺失代价 | 100 周期 |
| 基础 CPI（无访存停顿） | 2 |
| Load/Store 占比 | 36% |

```
I-Cache 缺失周期/指令 = 0.02 × 100 = 2
D-Cache 缺失周期/指令 = 0.36 × 0.04 × 100 = 1.44
实际 CPI = 2 + 2 + 1.44 = 5.44
理想 CPI = 2
理想 CPU 比实际快 5.44/2 = 2.72 倍
```

### 块大小的权衡

| 优点 | 缺点 |
|------|------|
| 大块利用空间局部性降低缺失率 | 块太大→块数减少→竞争增加 |
| 减少标签开销 | 缺失代价增大 |

> **最佳块大小**通常为 16~64 字节（4~16 字）。

### 经典例题

**题目**：某 CPU 基础 CPI=1，时钟 4GHz，主存访问时间 100ns。L1 Cache 缺失率 2%。求实际 CPI。

**解答**：
```
时钟周期 = 1/4GHz = 0.25ns
缺失代价 = 100ns / 0.25ns = 400 周期
实际 CPI = 1 + 0.02 × 400 = 9
```

## 7. 多级 Cache

### 知识点讲解

为了平衡速度和容量，现代处理器使用**多级 Cache**：

```
CPU → L1 Cache（小/快）→ L2 Cache（大/中速）→ 主存（慢）
```

### 设计目标

| 级别 | 设计重点 |
|------|----------|
| **L1 Cache** | 最小化命中时间（速度优先） |
| **L2 Cache** | 最小化缺失率（避免访问主存） |
| L1 块大小通常比 L2 块大小更小 |

### 多级 Cache 性能

**示例**：主存访问 100ns，L2 Cache 访问 5ns

| 配置 | CPI |
|------|-----|
| 只有 L1（缺失率 2%） | 1 + 0.02 × 400 = **9** |
| 加 L2（全局缺失率降至 0.5%） | 1 + 0.02 × 20 + 0.005 × 400 = **3.4** |
| **加速比** | **9/3.4 = 2.6 倍** |

### 经典例题

**题目**：L1 命中时间 1 周期，L2 命中时间 10 周期，主存访问 200 周期。L1 缺失率 5%，L2 缺失率 20%（相对于 L1 缺失）。求 AMAT。

**解答**：
```
L1 缺失后访问 L2 的命中率 = 1 - 20% = 80%
全局缺失率（访问主存）= 5% × 20% = 1%

AMAT = L1命中时间 + L1缺失率 × L2命中时间 + 全局缺失率 × 主存时间
     = 1 + 0.05 × 10 + 0.01 × 200
     = 1 + 0.5 + 2
     = 3.5 周期
```

## 8. 虚拟内存

### 知识点讲解

**虚拟内存**将主存当作磁盘的"Cache"——每个程序拥有独立的虚拟地址空间，由操作系统和硬件共同管理地址翻译。

> **通俗理解**：虚拟内存就像一个"骗术"——程序以为自己有 4GB 的大空间（虚拟地址），实际上物理内存可能只有 1GB。操作系统负责把程序正在用的部分放在物理内存中，暂时不用的留在磁盘上。

### 关键概念

| 概念 | 说明 |
|------|------|
| **页（Page）** | 虚拟内存中的块，固定大小（通常 4KB） |
| **页错误（Page Fault）** | 要访问的页不在物理内存中 |
| **页表（Page Table）** | 存储虚拟页号到物理页号的映射 |
| **物理地址** | 实际访问内存的地址 |
| **虚拟地址** | 程序看到的地址 |

### 地址翻译

```
虚拟地址 = [虚拟页号(VPN) | 页内偏移(Offset)]
                ↓ 页表翻译
物理地址 = [物理页号(PPN) | 页内偏移(Offset)]
```

### 页表

页表是存储在物理内存中的数组，每个**页表项（PTE）** 包含：

| 字段 | 说明 |
|------|------|
| **物理页号** | 页在物理内存中的位置 |
| **有效位（Valid）** | 页是否在内存中 |
| **引用位（Reference）** | 页是否被访问过 |
| **脏位（Dirty）** | 页是否被修改过 |

### 页表大小计算

**32 位虚拟地址，4KB 页，4 字节/PTE**

```
页表项数 = 2³² / 2¹² = 2²⁰ = 1,048,576
页表大小 = 2²⁰ × 4 字节 = 4 MB/进程
```

如果有 100 个进程 → 400 MB 用于页表！

### 减少页表大小的方法

| 方法 | 说明 |
|------|------|
| **多级页表** | 常用的是二级页表，第一级索引大块 |
| **倒排页表** | 页表大小 = 物理页数，用哈希查找 |
| **页表分页** | 页表本身也可以被换出到磁盘 |

### 页错误处理

1. 使用出错的虚拟地址找到 PTE
2. 在磁盘上找到页的位置
3. 选择一个页替换（LRU 近似）
4. 如果被替换的页是脏的，先写回磁盘
5. 从磁盘读入新页，更新页表
6. 重新执行出错的指令

> 页错误代价：**数百万个时钟周期**（因为要访问磁盘）

### 经典例题

**题目**：虚拟地址 32 位，页大小 4KB，页表项 4 字节。求页表总大小。

**解答**：
```
虚拟地址空间 = 2³² 字节
每页大小 = 4KB = 2¹² 字节
页表项数 = 2³² / 2¹² = 2²⁰ = 1,048,576
页表大小 = 1,048,576 × 4 字节 = 4,194,304 字节 = 4 MB
```

## 9. TLB（快表）

### 知识点讲解

**TLB（Translation Look-aside Buffer）** 是 CPU 内部的一个高速缓存，用来缓存最近使用的页表项。

> **通俗理解**：页表在主存中，每次地址翻译都要去主存查页表（多一次访存）。TLB 就是页表的"Cache"——把常用的页表项放在 CPU 里，加速地址翻译。

### TLB 特点

| 指标 | 典型值 |
|------|--------|
| 大小 | 16 ~ 512 个 PTE |
| 命中时间 | 0.5 ~ 1 周期 |
| 缺失代价 | 10 ~ 100 周期 |
| 缺失率 | 0.01% ~ 1% |

### TLB 缺失处理

| 情况 | 处理方式 | 代价 |
|------|----------|------|
| 页在内存中（仅 TLB 缺失） | 从页表加载 PTE 到 TLB | ~10 周期 |
| 页不在内存中（页错误） | OS 从磁盘读取页 | 数百万周期 |

### MIPS TLB 缺失处理

MIPS 用**软件**处理 TLB 缺失：

```assembly
TLBmiss:
  mfc0  $k1, Context    # 获取缺失页的 PTE 地址
  lw    $k1, 0($k1)     # 加载 PTE
  mtc0  $k1, EntryLo    # 放入 EntryLo 寄存器
  tlbwr                 # 写入 TLB（随机位置）
  eret                  # 从异常返回
```

### TLB 和 Cache 的交互

```
CPU → TLB查找 → Cache查找 → 主存
        ↓缺失        ↓缺失
      查页表      从主存取数据
```

#### Cache 寻址方式

| 方式 | 描述 |
|------|------|
| **物理标记/物理索引** | 先 TLB 翻译，再用物理地址查 Cache（TLB 在关键路径上） |
| **虚拟标记/虚拟索引** | 直接用虚拟地址查 Cache，TLB 不在关键路径 |
| **虚拟索引/物理标记** | 用页内偏移（不翻译）索引 Cache，同时并行 TLB 翻译 |

### 经典例题

**题目**：TLB 命中率 99%，TLB 缺失代价 50 周期，页错误率 0.001%（TLB 缺失后），页错误代价 5,000,000 周期。求平均地址翻译时间。

**解答**：
```
TLB 缺失且页在内存中的概率 = 0.01 × (1 - 0.00001) ≈ 0.01
TLB 缺失且页错误的概率 = 0.01 × 0.00001 = 10⁻⁷

平均时间 = TLB命中时间 + TLB缺失×(页在内存代价) + 页错误×(页错误代价)
         = 1 + 0.01 × 50 + 0.0000001 × 5,000,000
         = 1 + 0.5 + 0.5
         = 2 周期
```

## 10. 存储器层次结构的通用框架

### 知识点讲解

**所有级别的存储器层次结构**（Cache、主存、磁盘）都遵循相同的四个问题：

| 问题 | 说明 |
|------|------|
| **Q1：块放置** | 一个块可以放在上层存储器中的哪些位置？ |
| **Q2：块查找** | 如何找到块？ |
| **Q3：替换策略** | 缺失时替换哪个块？ |
| **Q4：写策略** | 写操作如何处理？ |

### Q1：块放置

| 类型 | 放置规则 |
|------|----------|
| **直接映射** | 每个块只能放在一个特定位置 |
| **组相联** | 每个块可以放在一组中的 n 个位置之一 |
| **全相联** | 每个块可以放在任何位置 |

### Q2：块查找

| 层级 | 方式 |
|------|------|
| **硬件 Cache** | 用比较器并行比较 Tag |
| **虚拟内存（页表）** | 全相联，软件查找 |

### Q3：替换策略

| 策略 | Cache | 虚拟内存 |
|------|-------|----------|
| **LRU** | 2/4 路简单，高相联复杂 | LRU 近似（引用位） |
| **Random** | 接近 LRU，实现简单 | — |

### Q4：写策略

| 策略 | 描述 | 适用 |
|------|------|------|
| **写直达（Write-through）** | 同时更新 Cache 和下一级 | 低层次 Cache |
| **写回（Write-back）** | 只更新 Cache，替换时写回 | 高层次 Cache、虚拟内存 |

**写缺失处理**：
| 方式 | 描述 |
|------|------|
| **写分配（Write-allocate）** | 先取块到 Cache，再写入 |
| **写绕开（Write-around）** | 不取块，直接写下一级 |

### 经典例题

**题目**：比较写直达和写回策略在以下场景中的优缺点。

**解答**：
```
写直达优点：
- 替换时无需写回（下一级已有最新数据）
- 实现简单

写直达缺点：
- 每次写都要访问下一级（慢）
- 需要写缓冲（Write Buffer）缓解

写回优点：
- 写操作只到 Cache，速度快
- 同一块多次写只需一次写回

写回缺点：
- 需要脏位（Dirty Bit）记录块是否被修改
- 替换时可能需写回（增加替换代价）
```

## 11. Cache 一致性

### 知识点讲解

**Cache 一致性**是多核处理器中的关键问题——不同核的 Cache 中可能保存同一内存地址的不同副本。

> **通俗理解**：就像几个人同时看一份文件——如果一个人修改了，其他人的版本就过时了。需要一种机制确保所有人看到的是最新版本。

### 一致性的形式定义

1. P 写 X 后 P 读 X → 读返回写的值
2. P1 写 X，P2 读 X（足够时间后）→ 读返回写的值
3. P1 写 X，P2 写 X → 所有处理器看到写的顺序一致

### 监听协议（Snooping）

每个 Cache 监听总线上的读写操作：

```
P1 要写块 X → 发送 Invalidate（无效化）信号到总线
              → 其他 Cache 中的 X 副本被标记为无效
              → P1 获得独占访问权
```

### 目录协议（Directory-based）

使用目录记录每个块的共享状态，避免广播。

### 内存一致性

> **写完成**条件：一个写操作必须被所有处理器"看到"才算完成。

顺序一致性保证：
- P 写 X 然后写 Y → 所有看到新 Y 的处理器也看到新 X
- 处理器不能重排写操作

### 经典例题

**题目**：双核系统，初始 X=0。P1: X=1；P2: 读 X。如果使用写直达 Cache，什么情况下 P2 读到 X=0？

**解答**：
```
可能的情况：
1. P1 写了 Cache，但还没有写到主存
2. 写缓冲（Write Buffer）中的数据还没刷新到主存
3. P2 的 Cache 中还有 X=0 的旧副本（但写直达会更新内存）

解决方法：Cache 一致性协议（如监听协议）
- P1 写时广播 Invalid 消息
- P2 读时发现 Cache 中块已无效 → 从内存或 P1 的 Cache 中获取最新值
```

## 12. SRAM 与 DRAM 详解

### 知识点讲解

### SRAM（静态随机存储器）

**存储单元**：6 个晶体管（6T）构成一个触发器，可以稳定保持 0 或 1。

| 特性 | 说明 |
|------|------|
| **存储原理** | 双稳态触发器，有电就能保持 |
| **速度** | 快（0.5~2.5ns） |
| **集成度** | 低（6 管/位） |
| **功耗** | 较高 |
| **是否需要刷新** | 不需要 |
| **用途** | Cache |

#### SRAM 芯片组成

```
地址线 → 地址译码器 → 存储体（存储矩阵）→ I/O电路 → 数据线
控制线 → 片选/读写控制
```

- **单译码**：一个译码器，适合小容量
- **双译码**：行译码 + 列译码，减少选择线数量

**典型芯片**：6116（2K×8）、6264（8K×8）、62256（32K×8）

### DRAM（动态随机存储器）

**存储单元**：1 个晶体管 + 1 个电容（1T1C）。

| 特性 | 说明 |
|------|------|
| **存储原理** | 电容存储电荷 |
| **速度** | 较慢（50~70ns） |
| **集成度** | 高（1 管/位） |
| **功耗** | 低 |
| **是否需要刷新** | 需要（电容会漏电） |
| **破坏性读出** | 读出后需要重写 |
| **用途** | 主存 |

#### DRAM 地址复用

DRAM 将地址分两次送入（行地址 + 列地址）以减少引脚数：

```
A0~A7：地址输入线
RAS：行地址选通（Row Address Strobe）
CAS：列地址选通（Column Address Strobe）
WE：写使能
Din/Dout：数据输入/输出
```

**典型芯片**：Intel 2164（64K×1 位）

#### DRAM 控制器

```
DRAM 控制器 = 地址多路开关 + 刷新计数器 + 刷新/访存裁决 + 定时发生器
```

- 将 CPU 的信号转换为 DRAM 所需的 RAS/CAS 时序
- 管理刷新操作

### 经典例题

**题目**：SRAM 6116（2K×8）有多少根地址线和数据线？

**解答**：
```
2K = 2¹¹ → 11 根地址线（A0~A10）
8 位 → 8 根数据线（D0~D7）

加上控制线：CS（片选）、WE（写使能）、OE（输出使能）
```

## 13. 存储器扩展技术

### 知识点讲解

实际系统中，通常需要将多个存储器芯片组合成所需的容量和字长。

### 三种扩展方式

#### 位扩展（增加字长）

多个芯片的数据线并联，地址线共用。

```
用 8K×1 的芯片组成 8K×8 的存储器
→ 需要 8 个芯片
→ 地址线 13 根（8K）
→ 数据线 8 根（每芯片 1 根）
```

#### 字扩展（增加字数）

多个芯片的片选信号不同，数据线共用。

```
用 16K×8 的芯片组成 64K×8 的存储器
→ 需要 4 个芯片
→ 地址线 16 根（64K），其中 14 根片内，2 根选片
→ 数据线 8 根
```

#### 字位同时扩展

先位扩展再字扩展，或者反过来。

```
用 1K×4 的芯片 2114 组成 2K×8 的存储器
→ 位扩展：2 片为一组（4位→8位）
→ 字扩展：2 组（1K→2K）
→ 共需 4 个芯片
```

### 经典例题

**题目**：用 256K×8 的 SRAM 芯片组成 2048K×32 位的存储器，需要多少芯片？多少地址线？

**解答**：
```
位扩展：32/8 = 4 组（每组 4 片）
字扩展：2048K/256K = 8 组
总芯片数 = 4 × 8 = 32 片

总地址线：2048K = 2²¹ → 21 根
  其中片内：256K = 2¹⁸ → 18 根
  选片：3 根（8 选 1）
```

## 14. 校验码

### 知识点讲解

存储器在传输数据时可能出错，校验码用于**检测和纠正错误**。

### 奇偶校验码

在数据位后加 1 位校验位，使整个码字中 1 的个数为奇数（奇校验）或偶数（偶校验）。

```
偶校验位 C = x₀ ⊕ x₁ ⊕ ... ⊕ xₙ₋₁
奇校验位 C = NOT(x₀ ⊕ x₁ ⊕ ... ⊕ xₙ₋₁)

检错：F = x'₀ ⊕ x'₁ ⊕ ... ⊕ x'ₙ₋₁ ⊕ C'
  F=1 → 有奇数个错误
  F=0 → 无错误（或偶数个错误）
```

**局限**：只能检测奇数个错误，无法纠错。

### 海明校验码

通过多个校验位**不仅能检测错误，还能定位并纠正错误**。

#### 海明不等式

```
2ᵏ ≥ n + k + 1

n = 数据位数，k = 校验位数
```

#### 编码规则

1. 校验位 Pi 放在位号 2ⁱ⁻¹ 的位置
2. 每个数据位由多个校验位共同校验
3. 被校验位的位号 = 校验它的校验位的位号之和

#### 校验位分配

```
数据位 7 位 → 校验位 4 位 → 海明码共 11 位
排列：H11 H10 H9 H8 H7 H6 H5 H4 H3 H2 H1
      D7  D6  D5 P4 D4 D3 D2 P3 D1 P2 P1
```

| 校验位 | 校验的海明位号 |
|--------|---------------|
| P1 | H1, H3, H5, H7, H9, H11 |
| P2 | H2, H3, H6, H7, H10, H11 |
| P3 | H4, H5, H6, H7 |
| P4 | H8, H9, H10, H11 |

### CRC 循环冗余校验码

用于校验成块数据，检错率极高，硬件实现简单。

#### 编码方法

1. 有效信息 M(x) 左移 r 位
2. 除以生成多项式 G(x)
3. 余数 R(x) 即为校验位
4. CRC 码 = M(x)·xʳ + R(x)

**CRC 码能被生成多项式 G(x) 整除**——接收方用 G(x) 除收到的码，余数为 0 则正确。

#### 常用生成多项式

| 名称 | 多项式 |
|------|--------|
| CRC-12 | x¹² + x¹¹ + x³ + x² + 1 |
| CRC-16（IBM） | x¹⁶ + x¹⁵ + x² + 1 |
| CRC-16（CCITT） | x¹⁶ + x¹² + x⁵ + 1 |
| CRC-32 | x³² + x²⁶ + x²³ + x¹⁶ + x¹¹ + x¹⁰ + x⁸ + x⁷ + x⁵ + x⁴ + x² + x + 1 |

### 经典例题

**题目**：数据位 0110001（7 位），求海明码。

**解答**（PPT 第 117 页）：
```
k=4（因 2⁴ ≥ 7+4+1=12 ✓）

排列：H11  H10  H9  H8  H7  H6  H5  H4  H3  H2  H1
      0    1    1   P4  0   0   0   P3  1   P2  P1

偶校验方程：
P1: H1⊕H3⊕H5⊕H7⊕H9⊕H11 = P1⊕1⊕0⊕0⊕1⊕0 = 0 → P1=0
P2: H2⊕H3⊕H6⊕H7⊕H10⊕H11 = P2⊕1⊕0⊕0⊕1⊕0 = 0 → P2=0
P3: H4⊕H5⊕H6⊕H7 = P3⊕0⊕0⊕0 = 0 → P3=0
P4: H8⊕H9⊕H10⊕H11 = P4⊕1⊕1⊕0 = 0 → P4=0

海明码：0110 0000 100
```

## 15. 高速存储器与并行主存

### 知识点讲解

为了缩小 CPU 和主存之间的速度差距，除了 Cache 外，还可以使用并行主存技术。

### 双端口存储器

同一个存储器有两套独立的读写控制线路，可同时访问。

### 多模块交叉存储器

将主存分为多个模块，连续地址分布在相邻的不同模块中，实现**流水式并行存取**。

#### 编址方式

```
模 M 交叉编址，M = 2ᵏ
第 i 个模块 Mi 的地址：M × j + i
其中 j = 0,1,...,L-1，i = 0,1,...,M-1
```

#### 访问方式

| 方式 | 描述 |
|------|------|
| **同时访问** | 所有模块同时启动，并行读写 |
| **交叉访问** | 模块轮流启动，间隔 = 单模块周期/M |

**交叉访问**示例（模 4）：
```
模块0: 0, 4, 8, 12, ...
模块1: 1, 5, 9, 13, ...
模块2: 2, 6, 10, 14, ...
模块3: 3, 7, 11, 15, ...
```

### 相联存储器

**按内容寻址**而不是按地址访问。用于 TLB 和 Cache 的 Tag 查找。

```
输入：关键字（Key）
比较：与所有存储单元同时比较
输出：匹配的单元
```

**组成**：
- 比较寄存器（CR）：存放要比较的数
- 屏蔽寄存器（MR）：指定比较哪些位
- 查找结果寄存器（SRR）：标记匹配的单元

### 经典例题

**题目**：模 4 交叉存储器，单模块存取周期 40ns。CPU 连续读取 4 个字需要多少时间？

**解答**：
```
顺序方式：4 × 40ns = 160ns
交叉方式：40ns + 3 × (40ns/4) = 40ns + 30ns = 70ns

加速比 = 160/70 ≈ 2.3 倍
```

## 16. 常见误区与陷阱

### 知识点讲解

### 陷阱 1：字节地址 vs 字地址

```
32 字节直接映射 Cache，4 字节/块
字节 36 → 块 36/4 = 9 → 9 mod (32/4) = 9 mod 8 = 块 1
字 36 → 36 mod 8 = 块 4

结果不同！务必区分字节和字！
```

### 陷阱 2：忽略存储系统对代码的影响

循环嵌套的顺序影响局部性：

```c
// 坏的顺序（按列遍历）→ 空间局部性差
for (i = 0; i < 500; i++)
  for (j = 0; j < 500; j++)
    for (k = 0; k < 500; k++)
      x[i][j] += y[i][k] * z[k][j];
```

> 上述代码的 MIPS 运行时间比优化循环顺序版本 **慢一倍**！

### 陷阱 3：用 AMAT 评估乱序处理器

乱序处理器在 Cache 缺失时仍可继续执行其他指令，甚至发出新的 Cache 请求——AMAT 不再准确。应使用**仿真**评估。

### 陷阱 4：多核处理器的 Cache 相联度

共享 L2/L3 Cache 时，相联度可能小于核心数 → 冲突缺失增加 → 更多核心需要更高相联度。

### 陷阱 5：右移不是除法

> **有符号数**右移 ≠ 整数除法！

```
-5 >> 2:
  逻辑右移：11111011 >>> 2 = 00111110 = +62 ❌
  算术右移：11111011 >> 2 = 11111110 = -2（接近但不等）
  
-5/4 = -1.25 → 整数除法截断到 -1 ✅
```
