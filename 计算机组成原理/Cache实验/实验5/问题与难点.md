# 实验5 Cache设计与实现：问题与难点

## 1. 实验任务理解

本实验要求在给定的 MIPS/SoC 环境中补全 Cache 模块。最低要求不是简单透传，而是实现写回策略的 Cache，并替换原工程中的 `i_cache.v` 与 `d_cache.v` 后通过 Vivado 仿真测试。实验资料还说明了 trace 比对机制：测试台会在写回寄存器时与 `cache_lab_trace.txt` 对比，从而判断 CPU 执行结果是否正确。

本次实现采用：

- I-Cache：4KB，直接映射，1 word/line，只读，命中时直接返回，缺失时从下级存储读入。
- D-Cache：4KB，直接映射，1 word/line，写回 + 写分配，包含 valid/dirty/tag/data。
- 写数据支持 byte、half、word 掩码合并，满足 `sb`、`sh`、`sw` 的写入需求。

## 2. 遇到的问题

1. 原始 `i_cache.v` 和 `d_cache.v` 是空模块，直接仿真会出现 `z` 值，CPU 侧无法得到 `addr_ok/data_ok`，单元测试先验证了这一失败现象。

2. 实验资料中有多种格式：PDF、PPTX、DOCX、DOC、MP4 和源码。PDF/PPTX/DOCX 可以抽取文字；旧版 `.doc` 用 Word COM 转换时超时，只能用字符串方式确认其主要是报告模板，不影响 RTL 实现判断。

3. 指导书对写缺失的描述有纠错文件：写回 + 写分配在写缺失时不能直接覆盖整行，必须先从内存读出原始 word，再按 size 和地址低两位合并写入，否则 `sb/sh` 会破坏同一 word 中未写的字节。

4. 类 SRAM 接口的握手容易出错。CPU 侧 `req` 可能保持到 `data_ok`，Cache 必须保证一次请求只接受一次；下级接口也必须在 `addr_ok` 后停止重复发同一个请求，等待 `data_ok`。

5. 脏行替换时写回地址不是当前访问地址，而是被替换行的 `{victim_tag, index, 2'b00}`。如果用当前 tag 组成写回地址，会把旧数据写到错误位置。

6. 原实验 Vivado 工程来自旧版本/旧器件，IP 最初按 `xc7a200tfbg676-2` 生成。在 Vivado 2020.2 中完整 SoC 仿真需要先升级并重新生成 `axi_clock_converter`、`axi_crossbar_1x2`、`clk_pll` 等 IP 的 simulation target，否则会报找不到 IP 仿真模块。

7. 目标板卡为 `xc7a100tcsg324-1`，但原工程 XDC 管脚约束属于另一块板卡，不能直接拿来生成该板子的 bitstream。本次对 Cache 顶层单独用 `xc7a100tcsg324-1` 做综合与 100MHz 时序检查，用原 SoC 工程做功能 trace 仿真。

8. 初版综合时 tag/data 数组在 reset 中清零，Vivado 将大量存储实现为触发器，资源占用偏高。后来只复位 valid/dirty 和控制寄存器，tag/data 由 valid 位保护，Vivado 能推断为 distributed RAM，资源显著下降。

## 3. 难点处理

- 状态机划分：D-Cache 使用 `IDLE -> WRITEBACK -> REFILL`。命中在 `IDLE` 内完成；干净缺失直接 `REFILL`；脏缺失先 `WRITEBACK`，写回完成后再 `REFILL`。
- 写回策略：写命中只更新 Cache 并置 dirty，不访问内存；只有脏行被替换时才向下级存储发写请求。
- 写分配策略：写缺失时一定先读入目标 word，再按 byte mask 合并 CPU 写数据，并把该行置 dirty。
- 掩码合并：根据 `size` 和 `addr[1:0]` 生成 4-bit byte mask，只更新有效字节。
- 复位策略：valid/dirty 清零即可保证冷启动不误命中，tag/data 不必清零。

## 4. Vivado验证结果

1. 单元测试：`tb_cache_unit.v`
   - 空 Cache 模块时输出 `TB_FAIL`，出现 11 个预期失败点。
   - 完成实现并优化后输出 `TB_PASS`。

2. 完整 SoC trace 仿真：`run_soc_sim.tcl`
   - Vivado/XSim 输出 `shell1 test begin.`
   - 输出 `dgemm PASS!`
   - 输出 `----PASS!!!`
   - 说明替换后的 Cache 通过实验包提供的 trace 对比测试。

3. 目标器件综合：`run_cache_synth_xc7a100t.tcl`
   - 目标器件：`xc7a100tcsg324-1`
   - 约束：`clk` 100MHz，周期 10ns。
   - 综合结果：0 errors，0 critical warnings，0 warnings。
   - 资源摘要：Slice LUTs 9248/63400，Slice Registers 3365/126800，DSP 0，Block RAM 0，LUT as Distributed RAM 3008。
   - 时序摘要：WNS 2.449ns，TNS 0，所有用户时序约束满足。
