2. 地址划分：tag / index / byte offset

源码中两个 Cache 都设置：

INDEX_WIDTH = 10

Cache 有 2¹⁰ = 1024 行。

OFFSET_WIDTH = 2

一行是 4 字节，也就是 1 个 32 位 word。

TAG_WIDTH = 20

32 位地址扣掉 index 和 offset，剩下 20 位 tag。

tagaddr[31:12]，20 位
indexaddr[11:2]，10 位
offsetaddr[1:0]，2 位
关键理解：因为每行只有 1 个 word，所以没有“块内第几个 word”的选择。低两位 offset 只用于 byte / halfword 写入时选择字节位置。

dirty

读命中

4.4 缺失路径：为什么要 saved 和 victim？

CPU 请求缺失保存本次请求到 saved_*，保存将被替换旧行到 victim_*。
旧行 dirty先进入 S_WRITEBACK，写回地址为 {victim_tag, saved_index, 2'b00}。
补充新行进入 S_REFILL，从内存读回新 word。
写缺失特殊处理如果 saved_wr=1，则把保存的写数据合并进刚读回的新 word，dirty 置 1。

6. 握手信号怎么读

信号含义源码中的行为
req请求有效CPU 或 Cache 发起一次访问。
addr_ok地址被接收Cache 在 S_IDLE 时接收 CPU 地址；外部模型在 req 有效时立即接收地址。
data_ok数据/事务完成命中时可与 addr_ok 同拍；缺失时要等 REFILL 或 WRITEBACK 完成。
addr_rcv地址已被下一级接收防止同一次缺失处理过程中重复向外部存储器发地址。
读源码口诀：CPU 侧看 cpu_*_addr_ok/data_ok，下一级存储器侧看 cache_*_addr_ok/data_ok。命中只走 CPU 侧，缺失才会走下一级存储器侧。

7. 满分答题口径

一句话概括

本设计实现了一个直接映射 Cache，其中 I-Cache 只读并在缺失时从外部存储器补充；D-Cache 采用写回和写分配策略，通过 valid/tag 判断命中，通过 dirty 位判断替换前是否需要写回。

老师追问时回答

缺失时必须保存 saved_*，因为等待外存期间 CPU 输入可能变化；脏块写回必须使用 victim_tag 和 saved_index 组成旧行地址，而不是用新请求地址。

常见问题速答

问题答案
为什么复位只清 valid/dirty？valid=0 时该行无效，tag/data 内容无意义，清大数组反而浪费资源。
为什么写命中不访问外存？D-Cache 是 write-back，写命中只更新 Cache 并置 dirty。
为什么写缺失要 refill？这是 write-allocate 策略，先把块调入 Cache，再在 Cache 中完成写入。
为什么需要 WRITEBACK 状态？当要替换的旧行 dirty=1 时，旧数据比内存新，必须先写回，不能直接覆盖。
