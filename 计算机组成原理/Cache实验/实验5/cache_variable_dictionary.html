0. 先看命名规则

cpu_*
CPU 侧接口。CPU 向 Cache 发请求，Cache 向 CPU 返回数据和握手。
cache_*
Cache 访问下一级存储器的接口。这里的 cache 不是数组，而是“Cache 对外发出的内存总线信号”。
*_inst_*
指令通道，用于取指，对应 i_cache。
*_data_*
数据通道，用于 load/store，对应 d_cache。
saved_*
缺失时保存 CPU 请求。因为等待内存期间，CPU 输入可能变化。
victim_*
保存被替换的旧 Cache 行。脏块写回时必须用旧 tag 和旧 data。

1. 类 SRAM 接口变量通用解释

这四个模块都围绕同一种握手机制写：req 发起事务，addr_ok 表示地址被接收，data_ok 表示事务完成。

变量后缀方向含义理解重点
req请求方 → 接收方请求有效CPU 或 Cache 说：“我要访问一次”。
wr请求方 → 接收方是否写1 表示写，0 表示读。
size请求方 → 接收方访问宽度00 字节，01 半字，10 字。I-Cache 和外部访问基本固定为 word。
addr请求方 → 接收方访问地址32 位字节地址。Cache 内部用它拆 tag/index/offset。
wdata请求方 → 接收方写入数据store 指令的数据。
rdata接收方 → 请求方读出数据load 或取指返回的数据。
addr_ok接收方 → 请求方地址阶段完成表示这次地址请求已经被接收。
data_ok接收方 → 请求方数据阶段完成读：数据有效；写：写事务完成。

2. cache.v：总封装接口变量

cache.v 本身不实现 Cache 算法，只把指令通道交给 i_cache，数据通道交给 d_cache。

变量类型含义作用
clkinput时钟所有状态机和寄存器在时钟上升沿更新。
rstinput复位清空 valid/dirty 和控制寄存器，使 Cache 从空闲态开始。
cpu_inst_reqinputCPU 取指请求CPU 想从 cpu_inst_addr 取一条指令。
cpu_inst_wrinput指令侧写使能接口保留信号。I-Cache 只读，本实现中基本不用。
cpu_inst_sizeinput取指访问大小接口保留信号。取指固定 32 位 word。
cpu_inst_addrinput取指地址I-Cache 用它拆出 tag 和 index。
cpu_inst_wdatainput指令侧写数据接口保留信号。I-Cache 不写，所以不用。
cpu_inst_rdataoutput返回给 CPU 的指令命中时来自 I-Cache，缺失时来自下一级存储器。
cpu_inst_addr_okoutputI-Cache 接收取指地址告诉 CPU：地址阶段完成。
cpu_inst_data_okoutputI-Cache 返回指令完成告诉 CPU：取指事务完成，rdata 有效。
cpu_data_reqinputCPU 数据访问请求load/store 都通过它发起。
cpu_data_wrinput数据侧写使能1 是 store，0 是 load。
cpu_data_sizeinput数据访问宽度决定 byte/halfword/word 写入合并方式。
cpu_data_addrinput数据访问地址D-Cache 用它拆 tag/index/offset。
cpu_data_wdatainputCPU 写数据store 写入的数据。
cpu_data_rdataoutput返回给 CPU 的 load 数据命中返回 Cache 行，缺失返回回填后的数据。
cpu_data_addr_okoutputD-Cache 接收数据地址告诉 CPU：地址阶段完成。
cpu_data_data_okoutputD-Cache 数据事务完成读：数据有效；写：写命中或写缺失处理完成。
cache_inst_*output/inputI-Cache 到下一级指令存储器接口I-Cache miss 时使用。
cache_data_*output/inputD-Cache 到下一级数据存储器接口D-Cache 写回和回填时使用。

3. i_cache.v：变量解释

3.1 参数和状态

变量类型含义源码中的作用
INDEX_WIDTHparameterindex 位宽这里是 10，所以 I-Cache 有 2^10=1024 行。
OFFSET_WIDTHparameter块内偏移位宽这里是 2，表示一行 4 字节，也就是一个 32 位 word。
TAG_WIDTHlocalparamtag 位宽32 - INDEX_WIDTH - OFFSET_WIDTH = 20。
CACHE_DEPTHlocalparamCache 行数1 << INDEX_WIDTH = 1024。
S_IDLElocalparam空闲态可以接收 CPU 新取指请求。
S_REFILLlocalparam回填态miss 后等待下一级存储器返回指令。
statereg当前状态在 S_IDLE 和 S_REFILL 之间切换。
addr_rcvreg外部地址是否已被接收防止同一次 miss 重复向下一级存储器发送地址。

3.2 保存请求和 Cache 数组

变量类型含义为什么需要
saved_tagregmiss 地址的 tag回填完成后写入 cache_tag[saved_index]。
saved_indexregmiss 地址的 index回填完成后知道该写入 Cache 的哪一行。
saved_addrregmiss 地址，低两位对齐为 0向下一级指令存储器发读请求。
cache_valid[i]reg array第 i 行是否有效valid 为 0 时，即使 tag/data 有值也不能算命中。
cache_tag[i]reg array第 i 行保存的 tag和当前请求 tag 比较，判断是否是同一个内存块。
cache_block[i]reg array第 i 行保存的 32 位指令命中时直接返回给 CPU。
iinteger循环变量复位时遍历清空 cache_valid。

3.3 组合逻辑信号

变量类型含义对应表达式/作用
req_tagwire当前 CPU 取指地址的 tagcpu_inst_addr[31:12]。
req_indexwire当前 CPU 取指地址的 indexcpu_inst_addr[11:2]。
hitwireI-Cache 是否命中cache_valid[req_index] && cache_tag[req_index] == req_tag。
idle_reqwire空闲态收到 CPU 请求只有这个为 1，才给 CPU addr_ok。
refill_donewire回填完成S_REFILL 状态下收到 cache_inst_data_ok。

4. d_cache.v：变量解释

4.1 参数、状态和控制寄存器

变量类型含义源码中的作用
INDEX_WIDTHparameterindex 位宽10 位 index，1024 行。
OFFSET_WIDTHparameter块内偏移位宽2 位 offset，一行 4 字节。
TAG_WIDTHlocalparamtag 位宽20 位。
CACHE_DEPTHlocalparamCache 行数1024 行。
S_IDLElocalparam空闲态接收 CPU load/store。
S_WRITEBACKlocalparam写回态miss 且旧行 dirty 时，把旧行写回下一级存储器。
S_REFILLlocalparam回填态从下一级存储器读入新行。
stateregD-Cache 当前状态控制 idle、writeback、refill 三个阶段。
addr_rcvreg地址已被下一级接收避免同一次写回/回填重复发送地址。

4.2 saved/victim：理解 D-Cache 的关键

变量类型含义为什么需要
saved_wrregmiss 时 CPU 请求是否是写回填后决定 dirty 是否置 1；写缺失需要合并写数据。
saved_sizeregmiss 时 CPU 访问大小写缺失回填后，用它判断写 byte/halfword/word。
saved_addrregmiss 时 CPU 原始地址回填地址、写数据合并的 byte offset 都要用它。
saved_wdataregmiss 时 CPU 写数据写缺失时，内存数据回来后再把它合并进去。
saved_tagregmiss 地址的 tag回填后写入 cache_tag[saved_index]。
saved_indexregmiss 地址的 index回填/写回都要定位到这一行。
victim_tagreg被替换旧行的 tag写回旧脏行时，用它拼出旧行原来的内存地址。
victim_datareg被替换旧行的数据写回脏块时作为 cache_data_wdata。

4.3 Cache 存储数组

变量类型含义判断/更新规则
cache_valid[i]reg array第 i 行是否有效复位清 0；回填成功置 1。
cache_dirty[i]reg array第 i 行是否脏写命中置 1；写缺失回填后置 1；读缺失回填后置 0；写回后清 0。
cache_tag[i]reg array第 i 行保存的 tag回填时更新为新请求 tag。
cache_block[i]reg array第 i 行保存的数据 word读命中返回它；写命中修改它；回填时写入新数据。
iinteger循环变量复位时遍历清空 valid/dirty。

4.4 组合逻辑信号

变量类型含义源码中的作用
req_tagwire当前 CPU 数据地址的 tagcpu_data_addr[31:12]。
req_indexwire当前 CPU 数据地址的 indexcpu_data_addr[11:2]。
req_hitwireD-Cache 是否命中valid 为 1 且 tag 相等。
idle_reqwire空闲态收到 CPU 请求只有此时才接收 CPU 地址。
hit_donewire命中访问完成命中读/写都可在同一拍完成。
refill_donewire回填完成下一级存储器返回 cache_data_data_ok。
hit_write_wordwire写命中合并后的 word把 cpu_data_wdata 合并进旧 cache_block。
refill_write_wordwire写缺失回填后合并的 word先从内存读回 word，再把保存的写数据合并进去。
refill_final_wordwire最终写入 Cache 的回填数据读缺失用内存数据；写缺失用合并后数据。
old_wordfunction input原 32 位 wordmerge_write_data 的输入，被部分字节覆盖。
write_datafunction input要写入的数据byte/halfword/word 的来源。
sizefunction input写入宽度决定掩码是 1 字节、2 字节还是 4 字节。
addr_lowfunction input地址低两位决定从 word 的哪个字节开始写。
maskfunction reg字节写掩码mask[0] 对应低 8 位，mask[3] 对应高 8 位。
merge_write_datafunction return合并后的 32 位 word用于写命中和写缺失。

5. cache_board_top.v：板级自测变量解释

这个文件不是 Cache 算法本体，而是一个“自测平台”：模拟 CPU 请求、模拟下一级存储器，用 LED 显示测试结果。

5.1 顶层控制和失败标志

变量类型含义作用
clkinput板上时钟驱动自测 FSM、存储器模型和 Cache。
rstinput复位重新开始自测。
ledoutputLED 输出显示是否完成、是否成功、失败码和状态码。
statereg板级自测状态控制测试按取指 miss、取指 hit、D-Cache miss、写命中、脏块写回顺序执行。
failreg失败标志寄存器每一位对应一个检查项，任意位为 1 表示对应测试失败。

5.2 自测 CPU 侧信号

变量类型含义作用
cpu_inst_reqreg模拟 CPU 发取指请求自测 FSM 拉高它来测试 I-Cache。
cpu_inst_wrreg模拟取指写使能一直为 0，因为取指是读。
cpu_inst_sizereg模拟取指大小设为 2'b10，表示 word。
cpu_inst_addrreg模拟取指地址测试中使用 0x00000100。
cpu_inst_wdatareg模拟指令写数据无实际作用，置 0。
cpu_inst_rdatawireCache 返回的指令自测检查是否等于 32'h90000100。
cpu_inst_addr_okwireI-Cache 接收地址自测 FSM 看到它后撤销 cpu_inst_req。
cpu_inst_data_okwireI-Cache 返回完成自测 FSM 看到它后检查 cpu_inst_rdata。
cpu_data_reqreg模拟 CPU 数据访问请求用于测试 D-Cache load/store。
cpu_data_wrreg模拟 load/store0 为读，1 为写。
cpu_data_sizereg模拟数据访问大小测试 word 读和 byte 写。
cpu_data_addrreg模拟数据访问地址用 0x00000000、0x00000001、0x00001000 测试命中和冲突。
cpu_data_wdatareg模拟 CPU 写数据byte 写测试中使用 32'hAAAAAAAA。
cpu_data_rdatawireD-Cache 返回的读数据自测检查读回结果是否正确。
cpu_data_addr_okwireD-Cache 接收地址自测 FSM 看到它后撤销 cpu_data_req。
cpu_data_data_okwireD-Cache 数据事务完成自测 FSM 看到它后检查读写效果。

5.3 下一级存储器模型信号

变量类型含义作用
cache_inst_reqwireI-Cache 访问指令存储器请求I-Cache miss 时拉高。
cache_inst_wrwireI-Cache 是否写指令存储器固定为 0。
cache_inst_sizewire指令存储器访问大小固定 word。
cache_inst_addrwireI-Cache miss 回填地址指令存储器模型根据它生成返回值。
cache_inst_wdatawireI-Cache 写数据无实际作用，固定 0。
cache_inst_rdatareg指令存储器返回数据模型返回 32'h90000000 | addr[15:0]。
cache_inst_addr_okwire指令存储器接收地址这里直接等于 cache_inst_req。
cache_inst_data_okreg指令存储器返回完成延迟几拍后置 1。
cache_data_reqwireD-Cache 访问数据存储器请求写回或回填时拉高。
cache_data_wrwireD-Cache 是否写数据存储器写回脏块时为 1，回填读时为 0。
cache_data_sizewire数据存储器访问大小固定 word。
cache_data_addrwireD-Cache 访问下一级地址写回时是 victim 地址，回填时是 saved 地址。
cache_data_wdatawireD-Cache 写回数据来自被替换脏行。
cache_data_rdatareg数据存储器返回数据根据地址 bit12 返回 data_mem0 或 data_mem1。
cache_data_addr_okwire数据存储器接收地址这里直接等于 cache_data_req。
cache_data_data_okreg数据存储器事务完成延迟几拍后置 1。

5.4 存储器模型内部变量

变量类型含义作用
inst_delayreg指令存储器响应延迟计数器模拟外部存储器不是立刻返回。
inst_pending_addrreg指令存储器已接收但未返回的地址延迟结束后根据它生成 cache_inst_rdata。
inst_readsreg指令存储器读次数用于验证第二次同地址取指是否命中，不能再次读外存。
data_mem0reg数据存储器测试 word 0初值 32'h11223344，地址 bit12 为 0 时访问。
data_mem1reg数据存储器测试 word 1初值 32'h55667788，地址 bit12 为 1 时访问。
data_delayreg数据存储器响应延迟计数器模拟数据存储器访问延迟。
data_pending_wrreg等待完成的数据访问是否为写延迟结束后决定写入还是返回数据。
data_pending_addrreg等待完成的数据访问地址延迟期间保存地址。
data_pending_wdatareg等待完成的数据写入值写回完成时写入 data_mem0/1。
data_readsreg数据存储器读次数验证 D-Cache 命中时不会再次读外存。
data_writesreg数据存储器写次数验证写命中不写外存，脏块替换才写回一次。

6. 状态变量速查

状态所在文件含义下一步
S_IDLEi_cache / d_cache空闲，可接收 CPU 请求命中则完成；缺失则进入回填或写回。
S_REFILLi_cache / d_cache从下一级存储器读入缺失块收到 data_ok 后写入 Cache，回到 idle。
S_WRITEBACKd_cache把被替换的脏行写回内存写回完成后进入 S_REFILL。
ST_I1_REQcache_board_top第一次取指请求测试 I-Cache miss。
ST_I1_WAITcache_board_top等待第一次取指返回检查返回值和外存读次数。
ST_I2_REQcache_board_top第二次同地址取指测试 I-Cache hit。
ST_D1_REQcache_board_top第一次数据读请求测试 D-Cache 读 miss。
ST_D1_WAITcache_board_top等待第一次数据读返回检查读到 11223344。
ST_DW_REQcache_board_top字节写请求测试写命中、dirty 置位、不立刻写外存。
ST_D2_REQcache_board_top读回原地址检查 byte 写合并结果 1122AA44。
ST_DC_REQcache_board_top访问冲突地址触发脏行写回 + 新行回填。
ST_DC_WAITcache_board_top等待冲突访问完成检查写回次数和写回内容。
ST_DONEcache_board_top自测完成LED 显示结果。

7. 按访问流程记变量

I-Cache miss 流程

cpu_inst_req + cpu_inst_addr ↓ 拆地址 req_tag / req_index ↓ 判断 hit = valid[index] && tag[index] == req_tag ↓ miss saved_tag / saved_index / saved_addr ↓ 访问下一级 cache_inst_req / cache_inst_addr ↓ 返回 cache_inst_data_ok / cache_inst_rdata ↓ 写入 Cache cache_valid / cache_tag / cache_block

D-Cache 脏块替换流程

cpu_data_req + cpu_data_addr ↓ 拆地址 req_tag / req_index ↓ miss saved_* 保存新请求 victim_* 保存旧行 ↓ 如果旧行 valid && dirty S_WRITEBACK: cache_data_addr = {victim_tag, saved_index, 2'b00} cache_data_wdata = victim_data ↓ 写回完成 S_REFILL: cache_data_addr = {saved_addr[31:2], 2'b00} ↓ 回填完成 cache_valid = 1 cache_dirty = saved_wr cache_tag = saved_tag cache_block = refill_final_word
最重要的一句话：saved_* 是“新请求”，victim_* 是“旧行”。写回用 victim_*，回填用 saved_*。
