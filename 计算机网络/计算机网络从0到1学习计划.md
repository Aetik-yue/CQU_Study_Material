# 计算机网络从0到1学习计划

> 目标读者：零基础、C++ 初学者、正在准备 RMDB 数据库大赛决赛的学生
> 总时长：约 **16 周**（每天 1.5~2 小时，周末可加量）
> 学习哲学：**一切协议都是"人和人之间的约定"，先懂人，再懂机器**

---

## 一、为什么这样安排（先看懂计划的设计逻辑）

### 1. 为什么用"自顶向下"顺序（从应用层开始，而不是物理层）

传统教科书（如谢希仁）从底层往上讲，先啃最枯燥的物理层，很多人第一周就弃坑了。
**自顶向下**（Kurose 教材的思路）从你每天都在用的东西讲起：

```
你打开 baidu.com          ← 应用层（第1步就学这个）
    ↓ 它需要 TCP 帮忙送数据  ← 传输层
    ↓ TCP 需要 IP 帮忙寻路   ← 网络层
    ↓ IP 需要网卡帮忙发信号   ← 链路层 / 物理层
```

**好处：每一层的学习动机都来自上一层的"未解之谜"。** 你会带着"上面那层到底怎么用我"的好奇心往下学，而不是背一堆不知道用来干嘛的定义。

### 2. 为什么给足 16 周

你是零基础，而且还有数据库大赛决赛要备赛。这份计划：
- 按 **每天 1.5~2 小时** 设计，不冲击比赛复习
- 每周只推进一个大主题，**宁慢勿快**
- 留了弹性：某周没跟上，直接顺延，不要跳过实验和自测

### 3. 你的独有优势：RMDB 就是活教材

你在 RMDB 内核里见过的东西，全部能映射到计网知识：

| RMDB 里见过 | 对应计网知识 | 在哪一周打通 |
|---|---|---|
| `sockaddr_in`、`port` 参数 | 端口 = 传输层地址 | 第 4 周 |
| 客户端连接服务器的整个流程 | TCP 三次握手 | 第 5 周 |
| `net::Buffer` 攒够一个完整请求才解析 | TCP 字节流 → 报文边界问题 | 第 5 周 |
| server 监听 client 请求的架构 | C/S 模型、socket 编程 | 第 13 周实战 |

学到对应章节时，我会提醒你回头看 RMDB 代码，你会突然发现："原来这行代码在做这件事！"——这种瞬间是计网学习中最爽的时刻。

## 三、每周学习节奏模板（固定不变）

```
周一~周三  看视频/读书，学新知识点（每天1个知识点，边看边在纸上画图）
周四      继续新知识 + 回顾本周前几天的笔记（合上笔记自己复述一遍）
周五      做本章习题（教材课后题或王道选择题）
周六      【动手实验】用 Wireshark 抓包验证本周所学（最重要的一环！）
周日      写"费曼笔记"：假装给一个完全不懂的人讲明白本周内容，
          讲不清楚的地方就是没学会的地方，下周一带回去重学
```

**三条铁律：**
1. **画图优先**：每学一个协议，必须在纸上画出"两台机器之间报文来回"的时序图。不会画 = 没学会。
2. **每个协议问三个问题**：①它解决什么问题？②报文长什么样（格式）？③状态怎么变化（如握手过程）？
3. **实验不许跳**：看懂 ≠ 会。抓包亲眼看到 SYN 包的那一刻，三次握手才真正进入你的脑子。

### 🍼 阶段〇：开胃课 —— 建立全局图景（第 0 周，约 5 天）

#### 本阶段解决的问题
"网络到底是什么？"——在钻进任何细节之前，先拿到一张地图。

#### 学习内容

**① 从生活出发理解网络**
把互联网想象成**全球快递系统**：

| 快递世界 | 网络世界 | 后面哪周展开 |
|---|---|---|
| 你写的信的内容和格式 | **应用层**协议（HTTP 等） | 第 1~3 周 |
| 快递员收包裹、保证送到 | **传输层**（TCP/UDP） | 第 4~5 周 |
| 地址系统和分拣中心 | **网络层**（IP、路由器） | 第 6~8 周 |
| 两栋楼之间的运输车 | **链路层**（以太网、交换机） | 第 9~10 周 |
| 公路本身 | **物理层**（网线、光纤、电信号） | 第 11 周 |

**② 解剖一次上网经历（贯穿全程的主线悬念）**
在浏览器输入 `www.baidu.com` 按下回车，到页面显示出来，中间发生了什么？

现在你肯定答不上来。把这 15 个左右的问题抄在本子扉页上，当成本课程的"寻宝清单"，每学完一层就回来划掉几个：

```
□ "www.baidu.com" 这种名字是怎么变成 IP 地址的？（DNS）
□ 我的数据怎么找到百度服务器在哪？（路由）
□ 数据在路上会不会丢？丢了怎么办？（可靠传输）
□ 怎么保证没人偷看我发的密码？（加密/HTTPS）
□ 页面里的图片、文字是一次到的吗？（HTTP）
□ ……
```

**③ 工具安装**
- 安装 [Wireshark](https://www.wireshark.org/)（一路默认即可）
- 打开浏览器的开发者工具（F12），切到 Network 标签页，随便刷新一个网页，看看那一列列表——这就是你未来 16 周要搞懂的东西

#### ✅ 阶段产出（做完才算过关）
- [ ] 能对着家人说出"互联网 ≈ 全球快递系统"的三句解释
- [ ] Wireshark 安装成功，随便抓了 30 秒包（看到密密麻麻的列表即可，看不懂完全正常）
- [ ] 写下自己的"寻宝清单"
- [ ] 手绘一张"我家的设备 → 路由器 → 运营商 → 百度服务器"的连接示意图（瞎画没关系，第 14 周会重画对比）

### 🌐 阶段一：应用层 —— 你直接打交道的一层（第 1~3 周）

> 学完你能回答：浏览器和网站服务器是怎么对话的？域名怎么变成 IP？邮件怎么发出去的？

#### 第 1 周：应用层原理

**核心知识点**

| 知识点 | 要掌握到什么程度 | 生活类比 |
|---|---|---|
| 客户端-服务器模式 (C/S) | 能画出交互图；知道服务器=一直开机等人来连的店 | 餐厅（服务员=服务器进程，顾客=客户端） |
| P2P 模式 | 和 C/S 的区别；为什么 BT 下载越多人越快 | 大家互换各自的藏书，没有书店 |
| 进程间通信 & Socket | **重点**：socket 是"门的门把手"；结合 RMDB 的 `Socket` 类理解 | 电话通话：socket = 你手里的电话机 |
| 应用层协议的本质 | 协议 = 双方约定的报文格式 + 时序规则 | 点奶茶的话术模板："我要一杯→什么→多大→少冰" |
| 传输层服务需求 | 知道不同应用对"可靠性/速度"的要求不同 | 寄合同（必须可靠挂号信）vs 寄传单（撒出去就行） |

**动手实验①（周日）：第一次抓包**
1. 打开 Wireshark，选中自己的网卡开始捕获
2. 浏览器访问一个 http 网站（注意：很多网站强制 https，可访问 `http://httpbin.org/get`）
3. 停止捕获，在过滤框输入 `http`，找到那条 GET 请求
4. 点开它，看报文详情：能不能认出 `GET`、`Host:` 这些字？
5. **此刻不需要懂其他字段**，只需要感受到："原来报文就是一段有格式的文本，我能看懂它！"

**✅ 本周自测**
1. 用"餐厅"类比向别人解释什么是 C/S 模式
2. 为什么视频直播可以用 UDP 而网银转账必须用 TCP？（先凭直觉答，第 4 周回来验证）
3. RMDB 里 `Socket sock(AF_INET, SOCK_STREAM...)` 这行代码，`SOCK_STREAM` 表示想要哪种类型的"快递服务"？（提示：流式的、可靠的）

#### 第 2 周：HTTP —— 万维网的语言

**核心知识点**

| 知识点 | 要掌握到什么程度 | 生活类比 |
|---|---|---|
| HTTP 请求报文格式 | 默写出 GET 请求的结构行 + 首部行的常见字段 | 信封格式：收件人(Host)、事由(Method)、署名(User-Agent) |
| HTTP 响应报文 + 状态码 | 200/301/404/500 各代表什么场景 | 快递回执："已送达/改地址了/查无此人/快递公司内部着火了" |
| GET vs POST | 使用场景的区别 | GET=去柜台问信息，POST=递表格给柜台 |
| 非持久 vs 持久连接 | 会算"获取 N 个对象需要几个 RTT"（计算题常客） | 每买一件商品跑一趟超市 vs 一次性推购物车结账 |
| RTT 往返时延 | 定义 + 三次握手占多少 RTT（为第 5 周埋种子） | 喊一句话听到对方回应的时间 |
| Cookie | HTTP 无状态，Cookie 给它加了"会员卡"记忆 | 奶茶店会员卡：报手机号就知道你是谁、爱喝什么 |
| Web 缓存（代理服务器） | 为什么能加速；命中率概念 | 小区门口的便利店：不用每次都进城超市 |
| CDN 概念 | 内容分发到离你近的节点 | 全国连锁仓：就近发货 |
| HTTPS 是什么 | 只需知道 = HTTP + 加密（第 12 周揭晓原理） | 信件装进保险箱再寄 |

**动手实验②（周日）：亲手拆解一次网页加载**
1. F12 → Network → 刷新任意网页，观察：加载了几十个对象？第一个请求是谁？
2. Wireshark 过滤 `http`，找到一个 GET 请求和一个响应
3. 对照报文找出：请求方法、Host、状态码、Content-Type
4. 进阶：找一个带 Set-Cookie 响应头的网站，亲眼看到服务器发"会员卡"

**✅ 本周自测**
1. 手写一个最简 GET 请求报文（请求行 + 2 个首部行就够）
2. 页面 HTML 引用了 5 张图片：非持久连接（每次都要 TCP 建连）共需几个 RTT？（设每对象一个 RTT 传输）——这道题第 5 周学完握手后要重新精确计算
3. 关掉浏览器再打开购物网站，它还记得你的账号，靠的是什么机制？HTTP 本身记得吗？

#### 第 3 周：DNS + 电子邮件 + FTP

**核心知识点**

| 知识点 | 要掌握到什么程度 | 生活类比 |
|---|---|---|
| DNS 的作用 | 域名 → IP 的"电话簿" | 手机通讯录：记名字，不记号码 |
| 域名层次结构 | 根 → 顶级域(.com/.cn) → 权威服务器 | 总台 → 省分公司 → 具体营业点 |
| 递归查询 vs 迭代查询 | **重点难点**：能画出两种查询的完整时序图 | 问路：朋友帮你问到底(递归) vs 朋友告诉你该去问谁(迭代) |
| DNS 缓存 | 为什么第二次访问网站更快 | 自己记住常用号码，不用每次翻通讯录 |
| DNS 用 UDP 还是 TCP | 查询用 UDP(53端口)，区域传送用 TCP——为什么？（选择题常客） | 问一句号码(小事，喊一嗓子就行) vs 搬整本通讯录(大事，挂号寄) |
| SMTP / POP3 / IMAP | 发信用 SMTP(推)，收信用 POP3/IMAP(拉)；端口号 | 邮差收件(你推向邮局) vs 去邮局取件(你拉回) |
| FTP | 控制连接(21)和数据连接(20)分开——为什么？ | 点菜的服务员和上菜的传菜员是两个人 |

**动手实验③（周日）：玩转 DNS**
1. 命令行执行 `nslookup www.bilibili.com`，看返回的 IP
2. Wireshark 过滤 `dns`，刷新一个新网站，观察：查询-应答一对报文；找找 A 记录
3. 分别 ping 一个国内和国外网站对比延迟，体会"就近 CDN"

**✅ 阶段一总测验（做完才准进入传输层）**
1. 画出：浏览器访问 `www.example.com`（首次访问，无任何缓存）到收到首页为止的完整步骤图，至少包含 DNS 查询 + TCP 建连 + HTTP 请求响应三大环节
2. 递归 vs 迭代各画一张时序图
3. 解释为什么 DNS 主要用 UDP 而 HTTP 用 TCP
4. 回顾第 0 周的寻宝清单：现在能划掉哪几条了？

### 🚚 阶段二：传输层 —— 全书的皇冠（第 4~5.5 周）

> ⚠️ 这是整门课**最重要、考试分值最高、也是 RMDB 决赛最相关**的部分。进度慢下来，题目做多一点，完全值得花 2.5 周。
> 学完你能回答：数据怎么保证不出错不丢不失序？两台电脑上的程序怎么准确找到彼此？

#### 第 4 周：传输层基础 + UDP

**核心知识点**

| 知识点 | 要掌握到什么程度 | 生活类比 |
|---|---|---|
| 传输层存在的意义 | 网络层把包送到主机，传输层送到**进程**——从"找到那栋楼"到"找到那个人" | 快递送到小区(IP)后，还要靠门牌号交给具体住户(端口) |
| 端口号 | 0~65535；知名端口 80(HTTP)/443(HTTPS)/53(DNS)/21(FTP)；**会查会记** | 门牌号：同一栋楼里区分不同住户 |
| 多路复用与分解 | 发送时按端口贴标签(复用)，接收时按端口分发(分解) | 小区收发室大爷按门牌号分拣信件 |
| UDP 报文格式 | 8 字节首部：源端口/目的端口/长度/校验和——默写 | 快递单的最简版：只写"谁的、给谁" |
| UDP 特性 | 无连接、不可靠、面向报文、首部小、快 | 广播喇叭喊话：快，但不保证每个人听清 |
| UDP 校验和 | 会算（伪首部 + 反码求和），知道检错但**不纠错** | 封口贴纸：撕开过就知道被动过，但不知道少了什么 |
| UDP 适用场景 | 直播、DNS、游戏——为什么它们容忍丢包 | 传单撒街上，丢几张无所谓；合同绝对不行 |

**动手实验④（周日）**
1. `netstat -ano` 看本机正在监听的端口，对照知名端口号
2. RMDB 代码里搜索 `htons`，找到监听端口的那一行——这就是你的数据库"门牌号"
3. （可选）Wireshark 过滤 `udp`，随便找个 DNS 包，对照 8 字节首部逐字段认认

**✅ 本周自测**
1. 一台电脑同时开着微信和浏览器，消息/网页为什么不会串？完整说出"IP+端口"如何配合工作
2. 默画 UDP 首部（4 个字段，各几字节？）
3. RMDB 服务端代码 `bind()` 绑定 8999 端口失败，可能的原因是什么？（提示：门牌号被占了）

#### 第 5 周：TCP 之可靠传输 —— 不丢、不错、不乱序

**核心知识点**

| 知识点 | 要掌握到什么程度 | 生活类比 |
|---|---|---|
| TCP vs UDP 总表 | 连接/可靠性/首部开销/是否字节流——这张对比表要刻在脑子里 | 挂号信专人签收 vs 街头发传单 |
| TCP 报文段首部 | 源端口/目的端口/序号/确认号/SYN/FIN/ACK/RST/窗口——逐字段认识 | 挂号信单据：编号、回执栏、签收状态 |
| 序号与确认号机制 | 序号=字节流的偏移量；确认号="期望对方下一个发的字节"；SYN 消耗 1 序号，纯 ACK 不消耗 | 读课文时手指指着当前位置："我说到第几个字了"、"我听到你讲到第几个字了" |
| 三次握手 | **必考**。画时序图 + 每一步的序号/确认号值 + **为什么恰好三次**(两次会导致旧的重复连接请求白白占用资源) | 对讲机通话："听得到吗？""听得到，你呢？""我也听到了，开始说正事" |
| 四次挥手 | 画时序图；**TIME_WAIT 为什么要等 2MSL**(确保最后的 ACK 到达 + 让旧报文自然消亡) | 挂电话前的反复确认："你说完了？""说完了""那我挂了？""嗯挂吧"(等一会确认没有遗言) |
| rdt 演进思想 | rdt1.0(理想信道啥都不用做) → rdt2.0(加校验+ACK+NAK) → rdt2.2(用 ACK 编号代替 NAK) → rdt3.0(超时重传对付丢包)——**理解每一步升级是为了对付哪个新问题** | 从"当面念清单"到"念完对方复述确认"再到"半天没回应就重念"的进化 |
| 滑动窗口 | 停止等待太慢 → 流水线并发发送；GBN(错了重发之后所有)与 SR(只重传缺失那个)的区别 | 发一批快递，每送到签收一个，窗口往前滑一格 |
| 超时时间估计 | RTT 平滑估计的思想（公式了解即可，重点是"为什么不能定死一个数"） | 外卖小哥估时：按最近几次的平均到达时间动态调整 |

#### 第 5.5 周：流量控制 + 拥塞控制（考试大题重灾区）

**核心知识点**

| 知识点 | 要掌握到什么程度 | 生活类比 |
|---|---|---|
| 流量控制 vs 拥塞控制的区别 | 流控=怕**对方**接不住(rwnd)；拥控=怕**网络**堵死了(cwnd)。发送窗口 = min(rwnd, cwnd) | 别一口气倒给室友太多外卖(他冰箱小) + 高峰期路上别挤太多单(平台限流) |
| 拥塞控制四大机制 | **慢启动**(指数涨) → **拥塞避免**(线性+1) → **快重传**(3个重复ACK立即重发) → **快恢复**(ssthresh=cwnd/2, cwnd=ssthresh) | 新司机上路先慢开试探路况，畅通则逐步提速，发现前方刹车灯连环亮立即减速 |

| ssthresh 的变化规则 | 超时：ssthresh=cwnd/2, cwnd=1 重来；快恢复：ssthresh=cwnd/2, cwnd=ssthresh | 严重事故封路从头排队 vs 小擦碰靠边让行继续走 |
| "慢启动"其实不慢 | 名字的坑：初始 1 很小，但增长是**指数**的 | 谣言传播：一个人传俩、俩传四个…… |

#### 第 8 周：路由算法与路由协议

**核心知识点**

| 知识点 | 要掌握到什么程度 | 生活类比 |
|---|---|---|
| 路由协议的分类 | 自治系统 AS 内部(IGP) vs AS 之间(EGP) | 小区内部的物业巡逻路线 vs 跨城物流要遵守的行业规范 |
| 链路状态(LS)算法 | 每个节点拥有全网地图，跑 Dijkstra 算最短路；会手动模拟 Dijkstra 的表格迭代(大题可考) | 先拿到全市地图再规划最优路线 |
| 距离向量(DV)算法 | 只跟邻居交换"我到各地的距离"，迭代收敛；理解无穷计数问题 | 只听邻居传闻估计路程，谣言传来传去才稳定，还可能越传越歪 |
| RIP | 基于 DV；最大 15 跳，16=不可达；每 30 秒交换 | 老式物流联盟：只信同行口口相传，超过 15 个中转站视为到不了 |
| OSPF | 基于 LS；收敛快、用于大型网络内部 | 每个站点持有完整地图，随时重算 |
| BGP | AS 之间的"政治协议"：不只看距离还看策略(商业关系)；路径向量 | 国与国通关：考虑外交关系而不只是地理远近 |
| SDN 概念 | 控制平面集中化(了解即可) | 原来每个路口各自思考，现在交由一个城市交通大脑统一调度 |

**✅ 阶段三总测验**
1. 一道 Dijkstra 手算大题：给定带权拓扑图，列出每轮迭代的候选节点表

### 🔒 阶段六：网络安全基础（第 12 周）

> 学完你能回答：HTTPS 到底加密了什么、怎么加密的？为什么公共 WiFi 上裸奔很危险？

**核心知识点**

| 知识点 | 掌握程度 | 类比 |
|---|---|---|
| 对称加密 | 加解密同一把钥匙；快；难题：钥匙怎么安全送达？ | 双方共用一把锁的钥匙，怎么把钥匙寄给对方不被偷？ |
| 非对称加密 | 公钥加密只有私钥能解；慢；解决钥匙分发问题 | 敞开的信箱(公钥)：任何人能投信，只有屋主持有信箱钥匙(私钥)能取出阅读 |
| 混合使用 | 实战 = 非对称交换对称密钥 + 对称加密传数据(又快又安全) | 先用挂号信寄一把新钥匙，之后日常通信都用这把新钥匙快锁 |
| 报文完整性与哈希 | MD5/SHA 特性(单向、雪崩)；HMAC | 封条：内容动一根笔画，封条纹路全变 |
| 数字签名 | 私钥签名 + 公钥验证 = 既证明身份又保证未篡改 | 亲笔签名+指纹，笔迹鉴定(公钥)人人可验，但仿造只有本人(私钥)能做到 |
| TLS/HTTPS 全流程 | **回收第 2 周的钩子**：TCP 建连 → 证书验证(防假冒) → 密钥协商 → 加密通信；能完整叙述 | 进银行先验柜员证照(证书)，再协商本日暗号(密钥)，之后全程暗语交易 |
| 防火墙 | 包过滤(按 IP/端口放行) vs 状态检测(概念) | 小区保安按名单放行车辆 |
| DoS/DDoS 概念 | 洪水攻击：一个人堵门 vs 组织一千个人堵门 | |

**动手实验⑨（周日）**

## 六、心态与答疑

**Q：某周进度落后了怎么办？**
A：顺延，绝不跳过实验和测验。这门课的知识层层咬合，跳过的洞会在后面变成悬崖。宁可 18 周学完，不要 14 周学虚。

**Q：视频和书先看哪个？**
A：视频为主(湖科大)，卡壳处翻书(自顶向下)。书是用来"查"和"深化"的，不是从头精读的。

**Q：需要背多少东西？**
A：真正需要"背"的很少：知名端口号、ABC类地址范围、几个公式(香农/奈奎斯特/最小帧长)。其余一切靠**画图+推理**就能现场推出来。凡是需要死记硬背才能记住的知识，说明还没真正理解——回到类比重讲给自己听。

**Q：什么时候可以开始和 RMDB 决赛联动？**
A：第 4 周(端口)起就可以对照源码了。建议第 13 周做项目前，专门花一个下午通读 RMDB 的 `net` 目录，你会发现 12 周所学在那里都有投影。
